# FileMint 实施路线

公开 TODO 见[中文主页](../README.zh-CN.md#未来规划)和 [English roadmap](../README.md#roadmap)。本文补充每项的实现思路与完成条件，方便开始一项工作时直接找到切入点。它描述未来工作，当前产品行为仍以 [SPEC](../specs/SPEC.md) 为准。

## 怎么使用这份路线

- 选择一个具体场景，先写清用户输入、目标目录、输出及失败时的行为，再更新 SPEC。
- 命名、模板、配置迁移和创建规则放在 `CorePackage`；设置放在 `App/FileMint`；原生创建面板放在 `SharedUI`；Finder 接口保留在 `FinderSyncExtension`。
- 完成实现后按 [HARNESS](../specs/HARNESS.md) 选择验证；分析和规划不默认跑测试。涉及 Finder 的部分按 [Finder 验收清单](FINDER_QA.md) 实机检查。
- 只有实现和验证都完成，才勾选中英文 README 对应项目；在发布说明里写明可用版本。未发布成果不写成当前下载版本已经支持。
- 官网通过 VitePress include 复用中英文 README 的 `roadmap` 区域。修改清单时保持区域标记、主题分组和 `- [ ]` / `- [x]` 格式；官网状态无需单独维护。
- 更新清单或官网后运行 `SITE_BASE=/FileMint/ pnpm run site:build`，检查中文和英文首页。README 变更已纳入 Pages 工作流触发范围，推送到主分支后才会触发线上部署。

### Homebrew tap（已公开 / 原生验收待完成）

**做什么：** FileMint 官方维护的 [Homebrew 安装源](https://github.com/FileMintApp/homebrew-tap) 已公开，可通过 `brew install --cask filemintapp/tap/filemint` 获取安装包。

**怎么做：** 复用正式 GitHub Release 的 DMG 和 SHA-256，先完成草稿候选精确验证、公开发布和适用的网站部署，再通过显式启用的发布钩子同步 tap。适配现有六产物、十字符串字段发布清单和恢复日志；保留 Sparkle 更新、Finder 扩展启用及文件夹授权边界。后续再评估官方 Cask 收录。

**怎样算完成：** 安装、升级、普通卸载、手动安装迁移、配置保留及版本同步均有验证。2026-10-13 tap 已公开，公开 CI、安装命令 dry run 和下载校验通过；用户暂时没有隔离 VM 或测试 Mac，原生验收阻塞，因此不勾选完成项。详细实现与证据见 [Homebrew tap 任务](tasks/homebrew-tap.md)。

## 模板与命名

模板拷贝与预览、创建后打开、模板导入导出已整理为[实施与验收任务](tasks/2026-10-05-template-workflow.md)，源码已实现默认关闭的功能开关、模板复制、逐模板与临时创建后动作、预览适配和事务化导入导出，自动检查与隔离原生夹具已通过；Office 预览提供器、真实编辑器与安装版 Finder 等原生验收仍待完成，详见任务证据。文件名规则继续保留在[原分阶段任务](tasks/2026-09-17-template-creation-workflow.md)中，尚未实施。

### 模板拷贝与预览

**已有基础与差距：** 当前已可编辑模板并在创建面板中查看预填内容，但没有模板复制入口和统一的保存前预览；图标预览不等于模板内容预览。

**做什么：** 拷贝一份模板再修改，保存和创建前看清最终文件名及初始内容。

**怎么做：** 拷贝时生成新的模板 ID；预览复用实际创建使用的命名和内容渲染规则。区分未修改的模板预览与用户已经编辑的草稿，切换模板时妥善处理已有输入。

**怎样算完成：** 修改副本不影响原模板；预览与实际文件一致；取消编辑不改变已保存模板；用户已输入的内容不会被无提示替换。

### 文件名规则

**已有基础与差距：** 当前日期等变量仅由 `TemplateRenderer` 展开到正文，默认文件名仍是保存的字符串；动态文件名规则尚未实现。

**做什么：** 通过日期、项目名称等字段生成常用文件名，创建前展示结果。

**怎么做：** 基于现有命名与变量渲染逻辑扩展，明确变量语法、缺省值、完整文件名的覆盖规则及同名策略。当前内容日期变量使用 UTC；若增加本地日期，需显式定义，保留旧模板输出语义。文件名和内容替换都应保持单次展开。

**怎样算完成：** 中文、空格、复合后缀、未知变量、跨日期边界及同名情况有明确结果；变量无法生成越出目标目录的路径；预览与最终命名一致。

### 模板导入导出

**已有基础与差距：** 当前可导入旧设置文件和单个 Office 文档模板，但没有独立模板包的导出、导入预览与冲突合并流程。

**做什么：** 在本地备份、迁移或分享一组模板，导入前确认内容和冲突处理。

**怎么做：** 定义带版本号的模板交换格式，支持选择导出范围。导入先校验再展示新增、跳过或另存为的结果；不把机器上的文件夹授权、更新状态和私有路径混入模板包。为已有 Office 文档模板一并定义资源打包与大小限制。

**怎样算完成：** 导出后重新导入能恢复模板内容与设置；未知版本、损坏文件和冲突不会破坏现有模板；取消导入不产生改动。

## 创建与后续操作

### 创建后打开

**已有基础与差距：** 当前成功创建后可在 Finder 中显示文件；“使用 App 打开”是独立菜单动作，尚未接入创建成功后的自动打开策略。

**做什么：** 创建后可继续在默认应用或用户选择的编辑器里工作。

**怎么做：** 在现有“创建后显示”偏好上定义完整策略，保留旧用户设置。只在写入成功后交给系统打开；脚本和可执行类型明确按编辑方式处理，不能意外执行。把“创建失败”和“文件已保存但无法打开”分开提示。

**怎样算完成：** 两条创建路径都遵循用户选择；打开失败不重复创建；未安装的编辑器可重新选择；偏好在重启和升级后保持。

## 目录与工具联动

### 项目目录模板

**已有基础与差距：** 当前创建服务处理单个文件或文档副本，尚无目录结构预览、批量生成及部分失败处理。

**做什么：** 从用户保存的结构一次创建资料、制作、交付等目录和起始文件。

**怎么做：** 在单文件模板与模板资源管理的基础上定义目录结构，创建前预览。明确同名、部分失败和取消的处理，首版限定符号链接、应用包和云端占位文件是否支持。输出路径必须留在目标目录内。

**怎样算完成：** 整套结构与预览一致；冲突不会改动已有文件；失败或取消只清理本次可确认安全清理的内容；大目录有进度或可理解的等待状态。

### 文件（夹）工具（已从路线图移出）

拷贝文件（夹）名称、拷贝文件（夹）路径、两步移动、彻底删除和隔空投送已作为独立的“文件（夹）工具”模块在 0.5.6 发布。模块默认关闭，主开关与每项开关可分别控制；每项还可选择显示在一级菜单或子菜单。菜单只针对已授权范围内的完整当前选择显示。彻底删除默认二次确认，隔空投送使用系统原生界面。详细操作、安全边界和安装方式见[发布说明](RELEASE_NOTES.md)与[安装指引](INSTALL.md)。

后续如增加 Shell 转义、相对路径格式或其他工具动作，会在这里重新以独立的未完成项目记录，而不会把已实现的名称/路径拷贝继续标为 TODO。

### 文件信息与四种校验值（已实现，Finder 基本流程已验收）

**做什么：** 在「文件（夹）工具 → 文件信息…」展示所选资源的基本信息，为普通文件计算 MD5、SHA-1、SHA-256、SHA-512，在原生弹窗内选择算法、主动计算，并支持拷贝和主动粘贴比对。

**怎么做：** 使用 Apple CryptoKit 流式计算所选摘要（支持一次选全部），主 App 提供可取消的原生信息弹窗；默认 SHA-256，选择 MD5 / SHA-1 时显示兼容性与安全提示；目录仅展示自身元数据，不递归扫描。本轮查阅的 Apple 文档未给出向 Finder「显示简介」注入摘要的公开接口，采用 FileMint 独立面板。独立任务包含官方资料、权限、内容变化检测、交互和阶段划分。

**怎样算完成：** 四种摘要与已知向量及独立工具一致，大文件内存有界、界面可响应；取消、授权失败、文件变化、链接和云占位有明确结果；实际 Finder 入口及权限另有原生证据。见[文件信息与校验值任务](tasks/2026-10-19-file-info-checksums.md)。

### 文件／文件夹密码加密保护（已封板，待重新讨论）

**做什么：** 通过独立的「文件密码」入口，对普通文件或明确选择的文件夹内容加密，统一管理主密码；首页优先呈现加密／解密，密码管理与恢复按需出现。没有正确密码或解密密钥时，不能通过 Finder 取消属性或重置应用设置恢复明文。

**当前状态：** 用户认为加密流程仍有待商榷，2026-10-19封板，等待明确重新开启。保留 Apple Encrypted Archive password 候选、私有暂存／完整验证及逐项可恢复迁移研究；右键加密、密码输入、原件处理和打开加密文件的流程尚未定案。封板期间不继续设计收敛、探针或产品实现；原型不代表最终方案批准。

**怎样算完成：** 正确密码可完整恢复，错误密码／篡改／截断不发布结果；目录结构与支持的元数据保真；原件处理经过完整解密验证，失败可恢复；密码迁移、沙盒、跨版本与独立安全复核有证据。2026-10-19隔离P0已验证password模式、目录样本往返和旧新密码流式迁移；发现20–256 UTF-8字节限制、部分明文和尾随数据处理边界。尚无产品功能、完整事务或新加密流程的签名沙盒证据。见[密码加密保护任务](tasks/2026-10-19-file-encryption-protection.md)。

### 快捷指令与启动器联动

**已有基础与差距：** 当前已有受控的目录/模板草稿 URL 和私有一次性票据，但没有面向这些启动器的完整名称/正文参数接口及经过验证的公开示例。

**做什么：** 作为目标版本的核心体验升级，本期让用户从快捷指令、Raycast 或通用 URL 带入名称、模板、内容和位置；配置有效时日常只填一个变化项，在清楚的草稿面板中确认后创建。Alfred 专用接入移至二期。

**怎么做：** App Intents 与版本化公开 URL 共用草稿链路，提供项目笔记、工作流文本、快捷搜索三个入门场景及 Raycast 本地导出。应用整体保持最低 macOS 13.0；接入功能单独要求 13.3，沿用单一 ForegroundContinuable 路线，不做低版本回退。13.0–13.2 上设置入口置灰并说明原因，直接外部调用同样拒绝；主 App、Finder extension、CorePackage 和分发元数据不提高最低版本。先贯通一个真实完整场景，再完善本期全部入口、首次接入指南和草稿首屏；本期设置不放 Alfred 占位。复用目标校验、单面板与授权边界，保留用户确认创建；公开链接不能绕过现有一次性快速创建凭据。

**怎样算完成：** Shortcuts、Raycast 均经真实入口验证，通用 URL 完成系统交付验证；至少 3 名首次使用者覆盖本期两种工具，仅凭界面与指南完成接入，日常固定工作流只填一个变化项，草稿第一眼能看懂文件、位置及待确认状态。畸形参数、未授权目录和重复请求不会静默写文件，已有草稿不丢输入；三项体验验收、可复现示例及对应最终版本的真实宣传素材均完成。应用与分发保持最低 macOS 13.0，接入功能在低于 13.3 时禁用，实际运行证据绑定所测环境；旧版历史记录保留原版本归属。

完整设计见[快捷指令与启动器联动方案](tasks/2026-10-29-shortcuts-and-launchers.md)：本期范围为 Shortcuts、Raycast 与通用 URL；应用最低 macOS 13.0，接入功能最低 13.3；macOS 13.0/13.3 实机运行尚未验证，产品能力尚未发布；Alfred 的导出、安装、实测和宣传留到二期。

## 查找与日常体验

### 模板分组与常用项

**已有基础与差距：** 当前模板保存 group 字段，创建面板已能按模板名和后缀搜索；模板管理页尚无用户分组和固定常用模板。“常用文件（夹）”管理的是文件位置，不代表模板收藏已完成。

**做什么：** 为场景模板分组、固定常用模板，模板变多后仍容易找到。

**怎么做：** 复用现有排序和创建面板按模板名、后缀搜索的规则，在模板管理页增加分组、常用项和搜索。Finder 保持紧凑；常用项由用户固定，不按使用次数自动重排。明确与旧启用状态和顺序的关系。

**怎样算完成：** 分组和常用项在重启后保持；搜索可找到同后缀的不同模板；删除或禁用模板后没有失效入口；菜单不会因模板增加而执行扫描或网络请求。

### 首次创建引导

**已有基础与差距：** 0.5.10 已提供扩展启用引导，当前也有目录授权和完全磁盘访问说明；尚无以真实首次创建结果为终点、可中断恢复的完整流程。

**做什么：** 帮用户从安装完成走到真正创建第一个文件。

**怎么做：** 基于已有扩展状态和目录授权界面设计短流程，允许跳过并稍后继续。每一步给出具体下一步；成功状态依据实际创建结果。保留不使用 Finder 扩展也能通过主应用创建的路径。

**怎样算完成：** 首次用户可以完成一次文件创建；拒绝授权、未启用扩展和中途退出可恢复；已配置用户不会反复被引导打断。

### 故障指引与兼容性说明

**已有基础与差距：** 官网已有中英文使用指南和常见故障处理，应用也有具体错误提示；跨云盘、外置卷的系统化验证记录及更完整的恢复引导仍待补齐。

**做什么：** 菜单缺失、目录不可写或创建失败时，让用户知道该如何处理。

**怎么做：** 区分已知的扩展状态、保存的目录授权、目标可用性及实际写入错误。延续完全磁盘访问不可自动检测的准确说明。建立桌面、普通目录、外置卷和各云盘的验证记录；如提供诊断导出，先展示内容并避开路径及文件正文。

**怎样算完成：** 常见失败场景有明确建议且保留草稿；帮助不把“已有书签”当作保证可写；兼容性说明注明实际测试环境和结果；未验证的环境不被描述为已支持。
