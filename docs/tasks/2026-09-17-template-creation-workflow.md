## Objective and scope

- 用户结果：同一种后缀保存多份场景模板；复制并预览模板；用日期和项目名称生成文件名；成功创建后继续在应用中编辑。

- 当前仅完成拆解，产品实现尚未开始；以下为实施方案，开始各项时先更新对应 SPEC。
- 范围：现有 UTF-8 文本模板、主应用设置、原生创建面板、Finder 快速创建和本地偏好迁移。
- 不包含：二进制文档模板、模板导入导出、目录模板、脚本执行、Shell 命令、自定义脚本表达式和发布。
- 完成条件：四项各自验收通过后，才勾选中英文 README 对应 TODO；未发布功能不得描述为当前下载版已支持。

| 后续规划 | 本次保留的扩展边界 | 本次避免的耦合 |
| --- | --- | --- |
| 模板导入导出 | 模板本身是可独立校验的数据；ID 冲突、排序和默认引用有明确规则；可选字段缺失可迁移 | 不把文件夹书签、机器路径、编辑器配置或更新状态塞进模板；未来交换格式单独版本化，不直接导出整个 Preferences |
| 真实文档模板 | 模板身份、后缀、显示信息与内容生成分开；当前文本渲染集中在明确边界，未来可新增资源复制实现 | 不在 UI、Finder、命名规则中散布 UTF-8 写入假设；不因后缀认定内容为文本或二进制；本次不改变现有纯文本范围 |
| 模板分组与常用项 | 所有选择、默认引用和操作基于稳定模板 ID；后缀只是属性；显示名称、分组、排序和启用状态各司其职 | 不用名称/后缀/列表位置当身份；不把是否默认等同于常用或分组；保留现有 group 数据，暂不重做分组 UI |
| 从剪贴板新建、图片粘贴 | 草稿来源、是否已编辑和内容生成模式独立；新入口可提交草稿或创建请求，再复用命名、冲突及结果处理 | 不让每个入口自己渲染模板或写文件；不自动读取剪贴板；本次只落实模板与原文模式，图像编码留待对应任务 |
| 项目目录模板 | 单文件请求、成功结果、冲突策略与后续动作分开；未来由上层编排多个文件并定义部分失败 | 不把单文件创建等同于“总是弹一个窗口/打开一个应用”；本次不建设事务引擎，也不承诺目录创建复用当前替换语义 |
| 复制文件名与路径、打开当前目录工具 | 原生系统交接与 Core 规则分离；应用选择和解析可复用，动作接受明确的文件或目录目标 | 不把工具联动硬编码到保存方法；不拼 Shell 命令；目录目标的授权和参数协议由未来任务单独定义 |
| 快捷指令与启动器联动 | 请求输入和渲染上下文独立于控件，外部入口未来可映射到相同草稿模型 | 不为复用而放宽单次票据、目标权限或用户确认；裸 URL 仍不能静默写文件 |
| 首次创建引导、故障指引与兼容性说明 | 写入结果与后续打开结果明确区分；保留可定位的失败阶段和重试边界，供未来引导展示 | 不把已保存但打开失败当创建失败；不依赖解析本地化错误文字作状态判断；不记录用户路径/正文 |

建议演进路径：入口输入 → 草稿/创建请求 → Core 命名及内容解析 → 文件写入 → 创建结果 → 原生后续动作。沿现有 `CustomFileDraft`、`FileCreationRequest`、`FileCreationService` 演进，仅提取实际存在的重复逻辑；预览复用纯解析步骤而不经过写入。

持久化数据和单次上下文分开：模板保存默认规则，草稿持有本次时间、项目字段和用户编辑；原生应用引用与目录授权仍归应用偏好。新增 Codable 字段提供兼容默认值和迁移测试，不无故重写已有模板 ID 或丢弃未知于当前 UI 的既有数据。

各阶段开始时先核对上表受影响行；若为了扩展需要跨入新的域契约，先加载并更新该域。阶段完成评审必须回答：下一个 roadmap 功能能从哪一处接入，是否仍需改写 Finder、面板和 Core 三套相同逻辑。若答案是需要三套重复实现，应先收敛当前边界。

## T1 — 同后缀多模板

Status: planned
Dependencies: none

- [ ] SPEC：后缀不再唯一，模板 ID 唯一；为后缀、默认文件名和模板身份明确独立语义，停止依赖 `Untitled.` 前缀反推后缀。
- [ ] Core：放开同后缀保存；草稿保留选中模板 ID，选择具体模板必须取该模板的内容与默认文件名。
- [ ] 默认选择：每种后缀可指定一个已启用默认模板；没有有效选择时，按已保存顺序选首个已启用模板，排序相同时按稳定 ID 决定。手输完整名称先保留匹配后缀的当前模板，否则采用该后缀默认模板；用户明确选择具体模板优先。
- [ ] 迁移：缺少新增字段的旧模板仍能加载；保留原 ID、正文、启用状态、顺序和其他偏好。旧默认由原有顺序确定；禁用、删除或更改默认模板后有确定回退。
- [ ] UI：设置能编辑独立的默认文件名、添加同后缀模板和设置默认；创建选择器显示模板名称与后缀并支持名称搜索；Finder 标签可区分，仍用模板 ID 分发。内置模板保持现有恢复机制，T2 支持复制后编辑。
- [ ] 草稿保护：已编辑名称、内容不会被模板切换静默覆盖；首版保留已有编辑，只有未编辑部分随模板更新。
- [ ] 覆盖：两份 `.md` 的编辑、选择、快速创建、面板创建；默认切换与删除/禁用；完整名称覆盖；复合后缀；旧 JSON 迁移及恢复内置后自定义项保留。
- [ ] 扩展评审：模板 ID、后缀、内容和显示信息独立；默认引用生命周期可被未来导入/删除复用，名称搜索不绑死预设格式。

验收示例：同时保存“会议记录”和“项目说明”，默认文件名分别为 `会议记录.md` 和 `README.md`；从两处入口创建时，各自名称、内容正确，重启后选择规则不变。

## T2 — 模板复制与预览

Status: planned
Dependencies: T1

- [ ] 复制内置或自定义模板，在编辑草稿中生成新 ID，沿用后缀、默认文件名与正文，名称加本地化副本标记；保存时插入源模板之后并启用，默认模板不随复制改变。取消不添加模板。
- [ ] 设置编辑器提供只读的文件名与初始内容预览，使用明确的示例上下文；预览不写文件，也不探测用户目录。
- [ ] 创建面板复用 Core 中同一解析结果；编辑源码与渲染预览分开，避免把预览结果当模板再次展开。已编辑的正文按原文预览和保存。
- [ ] 每份草稿捕获一次时间上下文，预览和本次创建共用；取消后新建草稿再获取新时间。快速创建在请求执行时捕获一次。
- [ ] 覆盖：副本互不影响、取消不保存、Unicode/空白/字面变量、已编辑草稿切换保护、固定时间下预览与实际字节相同。
- [ ] 扩展评审：预览通过纯解析边界获取结果；草稿来源与编辑状态可支持未来剪贴板入口，不在两种 UI 内各造一套规则。

验收边界：预览展示请求文件名与相应内容，不预留路径。并发创建导致同名时仍以独占写入结果为准；内容中的 `{{fileName}}` 必须使用实际落盘名称。面板继续保留覆盖确认，不能以“预览一致”为由绕过同名保护。

## T3 — 文件名规则

Status: planned
Dependencies: T1, T2

- [ ] 将规则明确绑定到模板默认名称，支持 `{{date}}`、`{{year}}` 和 `{{project}}`。日期保持 UTC，并在界面说明；首版不增加本地时区、任意日期格式或表达式语言。
- [ ] 为 `{{project}}` 提供模板内的默认项目值和面板中的本次覆盖值。缺值时预览提示并阻止提交；快速创建遇到缺值转入同一创建面板，补全后由用户点击创建，不猜目录名或自动写文件。
- [ ] 文件名规则单次展开，未知变量报可操作的校验错误；不把此规则应用到用户手填完整文件名。正文原有未知变量保留及 UTC 语义不变。
- [ ] 规则结果走统一文件名安全处理，界面预览处理后的结果；不得生成子路径。明确空值、中文、空格、点文件、复合后缀和同名编号位置。
- [ ] 先解析文件名，再用最终落盘名称渲染正文；同名递增时重新渲染正文中的文件名，但不重采样时间或二次展开替换值。
- [ ] 覆盖：UTC 跨日/跨年、项目缺值、未知变量、替换值包含变量、路径分隔符、手填覆盖、复合后缀、同名递增与并发不覆盖；两条创建路径均验证。
- [ ] 扩展评审：字段值通过明确的渲染上下文传入，渲染器不读取 UI、全局偏好、剪贴板或文件夹内容；新增受控变量只需扩展解析规则及测试。

验收示例：规则 `{{date}}-{{project}}-会议记录.md` 与项目值 `FileMint` 在固定 UTC 日期生成可预览的名称；输入 `临时记录.md` 后以手填名称为准，正文仍按对应模式处理。

## T4 — 创建后打开

Status: planned
Dependencies: 无功能依赖；按本任务顺序在 T3 后进行

- [ ] 定义单一创建后动作：无动作、在 Finder 显示、默认应用打开、指定编辑器打开。旧 `revealAfterCreation=true/false` 分别迁移为显示/无动作；不主动给旧用户开启打开功能。
- [ ] 确定性动作决策与偏好迁移放 Core，实际系统打开留在原生层；两条创建成功回调共用同一执行器，只接收成功结果的 URL。
- [ ] 指定编辑器由用户选择应用，保存可持久解析的应用引用；不改变系统默认打开方式，不拼接或执行 Shell 命令。
- [ ] 脚本、可执行文件及其他不能确认可安全打开的类型，不直接交给可能执行它们的默认处理程序；首版保守地引导选择已明确支持的文本编辑器，不能只依赖一个脚本后缀黑名单。具体原生 API 和沙盒行为须实测后定案。
- [ ] 打开失败单独提示“文件已保存，但无法打开”，提供显示文件、重新选择编辑器和重试打开；重试只针对已有文件，不重复创建。
- [ ] 覆盖：偏好往返与旧配置、创建失败时无后续动作、成功动作只触发一次、默认/指定应用、缺失编辑器、脚本按编辑方式处理、打开失败后的文件保留。用注入执行器做自动化，再做原生验证。
- [ ] 扩展评审：写入服务不启动应用；应用解析和打开错误独立于创建错误，后续目录工具或批量创建可自行决定何时执行动作。

验收示例：快速创建和面板创建都按偏好打开同一个已保存文件；移除编辑器后仍保留文件，选择新编辑器只重试打开，重启后偏好保留。
