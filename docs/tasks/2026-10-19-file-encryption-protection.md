## Objective and scope

- 最新需求：对文件／文件夹做真正的密码加密保护，统一管理一个密码；未取得正确密码或解密密钥时，Finder、其他软件或另一台电脑不能仅通过取消属性、改权限或重置 FileMint 设置恢复明文。
- 与文件信息／哈希任务分别规划、分别验收。哈希校验值不是加密，不共享密码含义或用哈希输出直接充当加密方案。
- 探索的首版：macOS 13+，一个普通文件或一个用户明确选择的普通文件夹，输出经过认证的加密归档；输入密码后解密到明确目的地。文件夹包含其授权范围内的目录结构与文件内容，不是只修改目录自身属性。
- 不包含实时透明加密、常驻挂载保险箱、文件系统驱动、多人共享、后台监控、自动云同步或后台遍历磁盘。批量多选、包／应用、符号链接、硬链接、跨卷和云占位兼容性另设门槛。
- 此前已按用户授权完成独立 P0，仅使用 synthetic 数据和公开测试口令运行 AppleArchive 探针并保存证据。当前阶段仅细化及审查方案，不运行新探针或进入产品实现；未访问用户 Keychain 内容、使用真实密码、加密用户资源、移除原件或发布构建。

## P0 当前结果（2026-10-19）

详细证据与可复查探针见[密码加密 P0 记录](evidence/2026-10-19-password-encryption-p0.md)。此前静态调研保留下文，当前实测结论优先：

- 本机 password profile 的输入边界为20–256 UTF-8字节；19／257拒绝，20／256完整往返。8–16位ASCII密码不适用。中文／Emoji可用，但全空格也通过，必须另设强度策略。NFC／NFD同外观密码不能互换，输入规则不能含糊。
- 目录样本的内容、嵌套／空目录、相对名称、mode、修改时间和测试xattr／资源叉往返一致；Swift API与Apple CLI双向互操作通过。不是任意目录／元数据兼容性保证。
- 改设置不会使新密码解开旧文件；可以旧密码解密流直接送入新密码加密流，验证新候选后替换。完整目录与64 MiB样本通过；中途抛错、进程终止和目标重名均保留旧归档。
- 离线旧副本仍需旧密码；批次中途可处于一部分新密码、一部分旧密码的真实混合状态。必须设计逐项迁移和恢复，不能宣称一次保存密码便全局完成。
- 晚期解密失败会留下部分明文；原生解密还接受尾部垃圾。必须私有暂存、完整认证、认证容器长度与固定源物理长度核对后再发布。认证头部／长度相等都不能替代完整内容验证。
- 新加密流程的签名 App Sandbox、真实密码UI／Keychain、旧系统、恶意归档解析和生产事务仍未验证。

## 安全目标与可承诺范围

目标是加密后静态密文的机密性和篡改检测。修改扩展名、移到另一电脑、绕过 FileMint UI、重置应用密码配置，都不能直接解出密文。正确实现、足够强的密码与私钥保密是前提；不能承诺弱密码不会被离线猜测。

- 密码必须参与密钥派生／解密，或用于解开真正的解密私钥，不能只验证一个 Bool 后使用常驻明文密钥。
- 加密不能防止有写权限的人删除、替换或破坏密文；需要备份，不能把加密称为不可删除。
- 明文原件、废纸篓、历史快照／备份、已导出的解密副本不因为生成密文而自动受保护。
- 资源解密后、加密磁盘挂载时或密钥存在进程内存期间，不能保证已获系统权限的其他软件无法接触明文。设备被控制、键盘记录、读进程内存等不属于这个离线文件保护承诺。
- 不增加“管理员密码／系统登录密码／Touch ID 可以重置后解开历史密文”的后门。以后增加替代解密方式必须明确改变安全目标。

### 本地 SDK 静态核对

读取当前 Command Line Tools SDK，没有编译／运行加密代码：

- `usr/lib/swift/AppleArchive.swiftmodule/arm64e-apple-macos.swiftinterface` 中 `ArchiveEncryptionContext` 标注 macOS 12.0；包含 password/scrypt 与 ECDHE profiles。与项目 macOS 13 目标无显见 availability 冲突，但不是旧系统运行证据。
- `usr/include/AppleArchive/AEAContext.h` 的 `AEAContextSetPassword` 注释明确存在内部密码字节长度范围，强度策略由调用方执行；文档未给出这里可直接承诺的具体上下限。必须在后续 P0 验证短密码、长口令、中文、Emoji 和 Unicode 处理，不能靠 SHA-256 后硬塞进 password 参数“解决兼容性”。
- `usr/include/CommonCrypto/CommonKeyDerivation.h` 提供 PBKDF2 与 HMAC-SHA256，并强调编码／规范化一致性。若原生 password profile 不满足输入／参数要求，可调研系统 KDF + AEAD 封装，但不能把旧示例中的迭代数当成当前安全建议。
- AEA `authData` 是公开的认证数据区域；不应把原文件名、路径、私钥或密码提示写进去。外部容器名称／总大小仍可见，是否隐藏内部名称及可见元数据需独立验证。

## 方案比较与当前推荐

| 路线 | 使用方式 | 统一密码与迁移 | 主要代价 | 首版建议 |
| --- | --- | --- | --- | --- |
| A. AEA 原生 password 归档 | 文件／目录变成密文归档；输入密码解密到目录 | 同一主密码用于各归档；正确密码及格式支持即可解开，不依赖单独私钥备份 | 改密码需要迁移已有归档；不能空手给离线副本换密码；加密时也需要密码材料 | 优先进行 P0，最直接对应 password 需求 |
| B. AEA 公钥归档 + 密码保护私钥 | 公钥负责加密；密码解开私钥后解密 | 改密码可只重新封装私钥，但换设备必须携带加密私钥备份 | 密码和密文都在却丢失私钥仍不能恢复；旧私钥封装副本和旧密码不能被远程撤销 | 若坚持冷启动后加密免输密码，再评估此路线 |
| C. 加密 DMG／稀疏映像 | 解锁后挂载，像磁盘一样编辑，用完推出 | 每个映像有密码；统一管理、改密码仍需管理全部映像 | 沙盒挂载、占用无法推出、打开期间明文可见、容量与云同步复杂 | 后续“保险箱”独立需求 |
| D. 自定义加密文件格式 | 自定义分块、头部、认证、恢复 | 可定制密钥封装 | nonce、截断／重排检测、版本兼容、解析器和恢复全由项目承担 | 首版不选；系统原语存在不代表自定义协议已经安全 |

**当前推荐 A：以 AppleArchive 原生 password 归档继续验证。** 这不是宣称 AEA 已满足全部产品要求；密码输入限制、目录元数据、沙盒及篡改检测都必须过新的 P0。若这些门槛不能满足，再比较 B 或其他成熟格式，不能悄悄降低加密强度。

此前“加密不输密码，解密才输入”的想法需要单独说明：对称 password 模式必须拿到密码材料才能加密。首版建议每次加密和解密均输入同一个主密码，不永久保存可直接解密的密码或密钥。若以后提供会话缓存，要有明确时限和结束条件；若要求退出／重启后仍免密码加密，路线 B 更符合这一目标。当前不把这项取舍视为用户已经确认。

## 统一密码的候选产品规则

1. 侧栏 Extensions 中独立的「文件密码」入口：首页以加密／解密为主，统一密码的设置、修改和已登记文件收进「密码管理」。密码用于真实加解密；不把它与系统登录密码或文件信息哈希混用。
2. 第一次启用需输入两遍长口令并说明不可恢复性。密码允许粘贴，不强迫用户在聊天中提供。具体字节范围／Unicode 规则待 P0；不能无提示 trim、截断或更改密码字符。
3. 路线 A 不保存可直接解密文件的主密码。可用带版本、使用同等级慢 KDF 保护的验证记录确认“当前主密码”，而不是无盐／快速哈希；可恢复迁移必须有持久的旧／新密码版本绑定依据，具体机制见本轮审查要求。Keychain 只作为额外存储保护，不能用独立 Bool 来绕过密文认证。参数、算法与输出边界需要安全复核。
4. 错误次数退避只改善 App 入口，无法阻止对复制出去的密文做离线猜测；因此密码强度与 KDF 才是主要防线。不允许因反复输错自动删除文件。
5. 修改主密码必须验证旧密码，并作为显式的逐项迁移任务执行：写新密文 → 独立完整解密校验 → 受保护的发布替换 → 持久记录该项完成。必须显示进度、支持中断恢复；只改配置不算旧文件已改密码。中断时同时显示旧／新密码版本，保留可恢复状态。具体事务要求见下文。
6. 仅维护用户明确导入或本应用生成的归档目录，不全盘扫描寻找密文。离线磁盘、他处副本和历史备份仍使用创建它们时的旧密码，不能承诺“全世界所有副本一起换密码”。不在未知旧归档全部迁移前声称只剩一个有效密码。
7. 忘记密码时不能通过“重置 FileMint”解开旧密文。没有活动迁移时，重置只能建立新的保护配置，并显著提示旧密文仍需旧密码；有活动迁移或未解决记录时不得覆盖其配置／恢复依据，须先走明确的任务结束或元数据救援流程。首版不默认生成另一个可绕过密码的恢复密钥；密码管理器／离线保存口令由用户自行选择。
8. 若后续选 B：把私钥用主密码经标准带盐慢 KDF 及认证加密封装；可研究以 AEA password 模式加密小型私钥备份。公开保存的只能是公钥和非秘密标识。仅保留加密私钥于本地／Keychain，解密私钥只在明确操作期间进入内存；不默认为 Touch ID 或系统登录替代主密码。
9. B 的换密码不是撤销旧私钥副本：拿到旧密码和旧加密私钥备份的人仍可解开同一密钥对应的数据。真正撤销需要轮换收件密钥并重新加密相关数据，且不能收回已经被复制的明文或旧密文。

## 文件与文件夹流程

主 App 的「文件密码」入口独立于文件（夹）工具；用户主动选择文件进行加密／解密。Finder 的「密码加密…」「解密…」是可选快捷入口，默认关闭，关闭它不影响主页面操作和恢复。Finder 具体菜单位置另在新领域 SPEC 固化，不复用文件工具模块开关。

### 原型反馈：独立入口与渐进呈现

- 用户反馈原型操作过于复杂；采用「文件密码」独立入口，不将迁移、日志和恢复状态机直接呈现为日常导航。
- 首页只突出「加密文件」「解密文件」及次要的「密码管理」。正常无任务时不显示恢复警告、进度表或技术能力清单；首次设置密码嵌入第一次加密，已有密码时直接进入选择／确认流程。
- 日常流程为明确选择资源 → 输入密码与确认保存位置 → 结果。默认保留原件／密文；在当前步骤说明结果，不增加重复确认和无必要的勾选。禁止把“加密副本生成”写成“原件已受保护”。
- 改密码仍是完整迁移事务，放在密码管理内。平常只显示已完成数、当前文件和「暂停／继续」；逐项列表、密码版本及故障细节按需展开。后台继续仅指用户已发起的活动操作，不增加扫描、监控或自动启动。
- 暂停后提供「先结束…」：一个简短确认页明确已更新／未更新数量、今后新加密所用密码及旧密码保留要求；同一已验证会话不重复要求密码或再加一层勾选。重启、会话失效或版本绑定不匹配仍须重新验证，完整执行 R9 的终止协议。
- 发生中断时才显示「上次修改还需要确认 → 继续处理」；自动选择协议允许的检查步骤，不要求用户理解发布意图等技术名词。证据不足不自动操作，必要授权与密码输入保持明确。存在未决原件动作时不能提供直接结束按钮。
- 恢复配置入口放在密码管理的「遇到问题？」中；已检测到配置异常时提升为首页提示。保留 R7／R9 的支持范围、证据分级及不覆盖规则，友好文案不能把拒绝／未确认状态伪装为成功。
- 以上是方案与交互原型调整，不是产品页面、Finder 入口或事务实现已完成。

### 加密

1. 捕获一个资源的冻结身份、范围和所需授权；弹窗展示目标、输出位置、主密码输入以及原件处置说明。只用元数据准备 UI，不在菜单生成时读内容。
2. 文件夹明确授权本次递归归档。首版不跟随符号链接／替身、不越过挂载边界，遇到不支持项整体报错，不悄悄漏文件。普通文件硬链接和 APFS clone／历史副本的外部明文风险不能靠目录内扫描消除。
3. 从经验证的源读取，直接流入加密输出；不先落一个明文压缩包。固定内存、限额、进度、取消与磁盘空间检查；检测到源变动时失败并保留原件，不声称获得所有非合作并发写入下的原子目录快照。
4. 使用目标目录内独占创建的私有密文暂存文件，完整关闭加密流并处理封尾错误。随后重新打开完整解密验证内容／结构；不把能读头部或计算密文哈希当成解密验证。密码模式可在同次操作短暂保留密码材料用于验证。
5. 校验通过才发布为完整归档，不覆盖已有目标。输出文件名可使用中性名称；原文件名和相对目录名进入加密部分。内部元数据隐藏和外部大小泄露需实测，不保证完全隐藏访问模式。
6. 默认保留原件时，结果必须写“加密副本已生成，原件仍未加密”。若目标是原位置只留密文，需要单独明确“验证后移除原件”，这属于后续待确认的不可逆处置，不能通过默认设置偷偷执行。
7. “移到废纸篓”不是彻底保护，因为废纸篓仍有明文；永久删除当前目录项也不证明 SSD、APFS 快照、备份和外部副本中的明文已消失。生产方案需将安全删除限制写进最终确认，不承诺安全擦除。失败／取消一律不删除原件。

### 解密

1. 选择受支持的密文 → 输入正确密码 → 选目的地 → 验证格式与认证 → 解密到私有暂存目录 → 完整成功后独占发布。
2. 明确提示输出是普通明文；默认保留加密归档。解密不是永久的“已解锁”属性，不自动替换／删除密文，也不后台盯着输出重新加密。
3. 归档输入视为不可信：限制条目数／总输出／压缩比，拒绝绝对路径、`..`、路径逃逸、符号链接／硬链接跳转、重复条目及大小写／Unicode 名称冲突；不恢复任意 UID/GID、ACL、可执行或系统保护位，不忽略错误继续发布。
4. 文件内容、相对名称、目录结构、空目录及必要 macOS 元数据保真由 P0 建立清单；资源叉、扩展属性等无法保留时不得静默丢弃并删除原件。不得顺便清除 quarantine 等安全属性。
5. 错密码、头部被改、内容篡改、截断、取消或空间不足都不发布“完成”输出。清理仅限本次可确认归属的暂存；清理失败明确提示残留明文位置，不声称已经重新受到保护。

## 已确认的实施硬门槛（2026-10-19）

以下是用户在 P0 后明确要求的后续设计约束，不是现有产品功能或已完成验证。实施前须纳入独立 encryption 领域 SPEC。

### 解密输出与完整验证

- 所有可能输出明文的路径，包括正常解密、加密后回读及迁移候选验证，必须使用受控接收器；需要落盘时只写本次独占创建的私有暂存区。不能先写最终目的地，再因认证失败尝试撤回。暂存区在创建时即限制访问（目录 0700、普通文件 0600），位于已授权且支持所需发布语义的位置；不能用“隐藏文件名”代替私有权限。
- 解包不能通过路径穿越、绝对路径、链接或归档自带权限扩大访问、逃出暂存区；未认证完成的内容不能交给 Finder、预览或其他消费者。私有权限不代表能抵御同身份或更高权限进程，也不承诺安全擦除。
- 对固定打开的同一源对象，认证属性后核对认证容器长度与实际物理长度；不一致必须拒绝，包括尾随垃圾、拼接另一容器或截断。检查覆盖整个输入文件，不能先裁剪到声明长度再让原生 API 接受。
- 长度一致后仍须完整读取、认证全部内容，完成归档结构／支持项校验，并检查所有流的结束和关闭错误；发布前重新核对源身份与变更状态。任何一步失败都不发布，不能把认证头部、长度相等或原生 extract 成功单独作为通过条件。检查不能消除的并发变更风险须在实现方案中处理，不能宣称仅凭大小检查获得了不可变快照。
- 完整验证后才以不会覆盖现有目标的方式发布结果。失败、取消和进程中断都保留源归档；仅清理已确认归属本任务的暂存，清理失败作为可恢复状态展示，重启后继续处理，不能显示“已清理”。明文残留位置只在用户需要处置的界面展示，不写入普通日志。

### 修改统一密码的迁移任务

迁移范围冻结为本应用生成或用户明确导入、授权的已知归档清单；离线、缺失或授权失效的项目必须留在清单中，不能通过扫描磁盘补齐或静默跳过。任务开始时明确旧／新密码版本与本次范围；活动迁移期间串行处理归档，并暂停新的加密和再次换密码，避免范围与密码版本漂移。暂停不解除该限制；只有正常完成或按 R9 持久结束为部分完成／未执行后才解除。独立解密仍按具体归档需要的密码处理。

| 每项状态 | 必须完成的动作与恢复依据 |
| --- | --- |
| 待迁移／等待授权或上线 | 记录冻结的归档身份、密码版本和任务归属；重新取得精确授权后复核身份，不对同路径的替换文件操作 |
| 正在重加密 | 旧密码解密流送入新密码加密流，仅写私有密文候选；旧输入同样必须通过严格长度与完整认证门槛，完整封尾前不能进入下一阶段 |
| 正在验证 | 用新密码独立完整回读候选，验证内容与归档结构与本次旧输入一致；验证落盘明文也受私有暂存约束 |
| 待发布／发布中 | 先持久保存候选身份、验证结果和替换意图；复核旧归档身份，以具备恢复保障的替换事务提交，保留可恢复旧密文直到提交确认；不得先删除旧归档再移动候选 |
| 已迁移 | 新密文已发布且完成状态已持久保存；显示新密码版本。旧副本如仍保留须显式标记其仍用旧密码，不能当作已撤销 |
| 失败／已暂停／待恢复 | 保留原归档或已确认发布的新归档，记录失败阶段与清理状态；不能将未知提交结果算为成功，也不能自动覆盖重试 |

- 进度界面分别展示已迁移／总数、当前项和阶段、当前阶段已处理字节，以及待迁移、离线、失败数量；只有发布提交确认后才增加已迁移数。完整回读验证也计入工作，不能在写完新密文时提前显示 100%。
- 暂停或取消批次会停止后续项；当前项在安全点停止，尚未发布的候选不影响旧归档，已提交项目保留新版本。发布提交阶段须先完成或恢复到可判定状态，再报告暂停。取消不自动把已迁移项目改回旧密码。
- 持久恢复记录只存必要的任务／项目身份、版本、阶段及私有暂存引用，不存明文密码或可直接解密的密钥，也不把它们写入日志。密码只在本次操作内短暂使用；重启或会话结束后恢复须重新输入所需旧／新密码，并重新取得失效授权。
- 必须覆盖“新归档已经替换，但完成记录尚未写入”的崩溃窗口：恢复时依据持久意图、实际对象身份及完整认证结果判定当前版本；不能只相信阶段字段、路径或文件大小。结果有歧义时保留各候选并停在待恢复，避免再次迁移或丢失唯一可解副本。
- 未完成时显示混合密码状态；只在本次范围全部完成后报告“本次已知归档迁移完成”。离线项目不能算完成，范围之外的历史／备份副本仍需旧密码；不得提示用户旧密码已全局失效或可直接丢弃。

### 后续验收要求

- 晚期认证失败、截断、等长正文篡改、尾随垃圾、拼接容器及封尾／关闭错误：最终目的地无可见结果，源归档不变，暂存清理成功或留下明确可恢复状态。
- 在重加密、验证、替换前后及完成记录落盘前后分别注入取消、进程终止、写满／权限失败；恢复后每项必须至少有一份完整可解密版本，状态与实际旧／新密码矩阵一致，不覆盖并发替换的资源。
- 验证进度与真实阶段一致、混合版本可恢复、离线项上线后可续迁、清理失败不被隐藏、重新输入密码后可跨重启继续。重启恢复可以重新处理当前未提交项，不要求断点续传加密流。
- 以上是待实现的验收要求；现有 P0 只有样本观察，尚未证明生产私有暂存、完整事务、持久日志或崩溃恢复。不得用既有 SIGTERM 实验替代文件系统持久性验证。

## 迁移事务与崩溃恢复草案

本节细化上述要求，只定义拟采用的协议与失败处理；状态名是设计标识，不是已存在的类型或落盘格式。读取了现有 batch-rename 的意图记录、独占接管与提交后不回滚的实现作为边界参考，不直接复用其事务或据此宣称加密恢复已受验证。

### 事务单位、资源与不变量

- 一个批次固定旧密码版本 `vOld`、目标版本 `vNew` 和完整项目清单；每个归档独立提交，不做整批全有或全无。首版迁移仅拟支持经能力验证的本地 APFS 同卷文件操作；每项工作区与该归档同卷。不同项目可位于不同卷，但任一项不得降级为跨卷复制替换。具体文件系统／系统版本支持矩阵仍待验证。
- 归档身份至少绑定卷、实际父目录对象、普通文件对象及其代次信息，并记录密文字节长度／摘要。路径只用作定位提示，摘要只用作内容绑定，均不能替代对象身份与完整认证。拒绝链接、多硬链接、缺失或无法可靠识别的源；重新授权不会把同路径新文件变成原对象。
- 每项有随机且固定的 `itemID`、`attemptID` 和已登记的私有工作区 `W`。以下符号只表示该项的精确槽位：`O` 为用户原路径；`S` 为冻结的旧密文副本；`C` 为新密文候选；`R` 为接管后的旧原件。`S/C/R` 均在 `W` 内，本事务仅写自己登记的槽位，不假定权限能阻止同身份外部写入；不借助扫描目录寻找遗失项目。
- 原件始终至少保留至新密文及单项提交记录持久确认；失败或暂停不删除唯一可解密版本。这个保证针对本事务自身的动作和受支持的故障模型，不保证对抗外部删除、恶意同身份进程、硬件丢失或所有副本同时损坏。
- 本方案采用两次独占移动：`O → R`，确认接管对象正确后再 `C → O`。不使用先删除 `O` 再写入，也不使用会无条件覆盖任意目标的替换。两次移动不是一个原子动作，`O` 在两步之间会空缺，且接管后验证可能耗时；界面显示“正在提交／原路径暂不可用”，不能承诺无缝替换。若不能接受此行为，需要另行验证具有身份条件保护的替代协议，不能悄悄放弃并发保护。
- 只允许一个迁移写入者，恢复也须取得同一进程间排他权；锁由进程存活期管理，不能只凭残留 PID 文件判定锁占用。工作区权限不消除已有文件描述符的写入能力；前后状态检查、完整认证及密文比对用于检测变化，任意恶意并发写入下的快照保证不在当前承诺内。

### 持久记录与写入规则

恢复数据保存在专用私有事务存储，独立于普通设置。设置页只是状态投影，不能通过恢复默认设置、隐藏入口或导入设置遗忘活动迁移。

| 记录 | 最少内容 | 用途／限制 |
| --- | --- | --- |
| 批次清单 | schema 版本、批次 ID、原配置代次、`vOld/vNew`、冻结项目 ID、精确父目录授权引用、工作区预定名称、创建意图 | 在创建外部工作区前持久保存，重启仅从此清单定位已知位置；拒绝未知版本、越界规模与重复项目 |
| 单项事件 | 批次／项目／尝试 ID、递增序号、前事件绑定、意图或结果、已捕获的父目录／工作区／文件身份、密文长度及摘要、失败阶段与清理状态 | 每条完整编码且有长度边界和损坏校验；校验和不是防恶意篡改认证，记录中的路径不是写入授权 |
| 单项提交凭据 | `O` 中新对象身份、新密文摘要、`vNew`、对应验证及发布意图序号、尚存 `S/R` 引用 | 是“计入已迁移”的依据；不能被 UI 计数或一般进度事件替代 |
| 批次收尾记录 | 所有项目的提交凭据引用、配置激活意图／结果、待清理列表 | 连接配置与文件的不同持久化位置，避免先改设置后遗失未迁移项 |

记录不保存密码、明文摘要／文件清单、未封装密钥或原文内容。用于比较旧／新归档的完整解密字节流摘要只在内存中使用；重启后重新计算。密文摘要可持久保存，但不能作为密码正确或内容安全的证明。授权书签及必要定位信息仅留在私有存储，不进入普通日志或导出诊断。

本草案改用 R2 定义的预建固定记录槽：每条记录写入全新槽位，不在同一个变长文件的坏尾部后追加，不覆盖旧记录。先将意图记录持久确认，成功后才执行文件系统动作；动作及其目录变化持久确认后再写结果。槽位容量不足或记录链歧义都停止前进，按 R2 的有限恢复分支处理；不截断旧证据，不在活动事务中压缩记录。

这里的“持久化屏障”是需要证明的协议要求：文件数据与必要元数据、创建／移动／删除涉及的父目录项、记录本身及首次创建记录的目录项，都按顺序确认。仅 flush、close、原子 rename 或 API 返回成功不自动等于掉电持久化。原生文件／目录同步及更强落盘要求的映射、错误处理和支持范围须单独验证；不支持所需屏障则不得开始原件接管。App 私有记录与用户卷之间没有跨卷原子事务，靠先意图、后动作和重启核对处理窗口。

**任一写入或同步报告失败都可能留下已经可见的记录／移动结果。** 此时停止后续破坏性步骤，读取可用记录并核对实际槽位；不能仅因函数抛错便认为未提交并回滚。日志无法读取或继续持久化时，不再发布、回滚或清理用户资源，保持 `needsRecovery`，待记录能力恢复后显式继续。

### 单项状态转换与正常持久化顺序

主路径：`queued → preparing → building → validating → ready → claimIntent → claimed → publishIntent → published → committed → retainIntent → retained → cleaningTemporary → clean`。

`waitingAccess`、`waitingVolume`、`waitingPassword`、`paused`、`failed`、`conflict`、`storageBlocked`、`needsRecovery` 是执行阻塞原因，必须附带最后持久阶段及尝试 ID，不能覆盖或重置主路径。`published` 仍不计入已迁移；`committed` 及其后续保留／临时清理状态才计入。不存在从 `committed` 自动回到旧密码的转换。

| 顺序／状态 | 必须按此顺序执行 | 失败时的边界 |
| --- | --- | --- |
| 0 `queued` | 校验旧密码与配置代次；两次确认新密码并拒绝按已冻结输入规则得到的相同旧／新密码；按下述批次开始协议先保存清单及开始意图，再写迁移中配置，最后确认批次开始；然后允许创建工作区 | 保存失败不开始文件迁移；配置写入结果不确定时核对后恢复，不能假定写入未生效。空清单需明确提示只改变今后新归档的密码，不声称发现并迁移历史副本 |
| 1 `preparing` | 写工作区创建意图 → 独占创建 `W` → 确认权限／身份并同步目录 → 记录工作区身份 → 写 `S` 创建意图 → 独占创建空文件并持久登记身份 → 从固定打开的 `O` 复制到 `S` → 同步 `S/W` → 检查源前后状态并登记完成长度／密文摘要 | `O` 未变；不完整 `S` 不可信。工作区创建后身份记录前崩溃，只有名称／意图不足以证明归属，转待恢复，不能认领同名目录或递归删除 |
| 2 `building` | 从冻结后不再写入的 `S` 认证属性／核对精确长度 → 记录候选创建意图 → 独占创建空 `C` 并持久登记身份 → 旧密码解密流送入新密码加密流，同时对完整解密流计算内存摘要；完整消费、认证旧输入并完成结构校验 → 完整封尾、关闭 `C` → 同步 `C/W` → 记录候选身份／密文摘要 | 任一认证、读取、写入或关闭错误均不得进入验证完成；`O/S` 保留，候选视为未验证，不因能打开头部而复用 |
| 3 `validating` | 重新只读打开 `C`，新密码完整认证、严格长度检查、归档安全校验，解密流摘要／长度与本次 `S` 的完整流一致 → 按 R7 应用并读回外层元数据 → 同步并确认内容／元数据均绑定 → 写 `ready` 验证结果并持久化 | 验证错误保留 `O/S`，清理仅限确认归属的候选。若中断导致内存摘要丢失，重新完整验证 `S/C`，不使用持久 `ready` 绕过内容验证 |
| 4 `claimIntent` | 固定父目录及 `W` 句柄，重新核对 `O` 身份 → 持久保存 `O → R` 意图，含预期对象身份／槽位 → 独占移动 `O → R` → 同步两个目录 → 核对 `R` 实际对象身份、完整旧密码认证、密文与 `S` 一致及 R7 冻结元数据未变 → 持久保存 `claimed` | 移动调用失败也先核对位置。误接管了其他对象时不读取其内容，只在原槽空缺、身份仍匹配且有持久恢复意图时独占归还；有冲突则保留并停止。源内容变化或完整认证失败不发布 `C` |
| 5 `publishIntent` | 确认 `R` 可恢复、`C` 仍是已验证对象、父目录未换、`O` 空缺 → 持久保存 `C → O` 意图 → 独占发布 → 同步 `W/父目录` → 核对 `O` 为新对象且 R7 发布后元数据满足预期 → 持久保存 `published` | 目标被占用不覆盖、不合并；保留 `R/S/C` 中实际存在的对象。任一同步不确定转核对，不自动把 `R` 覆盖回 `O` |
| 6 `committed` | 确认新对象与候选验证绑定未变化；重启恢复场景须重新完整验证 → 持久写入单项提交凭据 → 更新派生进度／版本 | 提交凭据写入或同步失败时保留 `R/S`，不计完成、不清理、不直接回滚；可能已写成的凭据需读回判定并重新完成屏障 |
| 7 `retainIntent/retained/cleaningTemporary` | 提交明确持久后，先登记 `R` 为保留旧原件并持久确认 → 对可丢弃的 `S` 及本事务验证暂存逐个写清理意图 → 复核归属后清理并同步 → 写结果 | 绝不自动删除、截断或重加密 `R`；登记或暂存清理失败为待收尾，不倒退提交状态。发现对象被替换或变化则保留并停为冲突 |
| 8 `clean` | 可丢弃暂存清理完成、`R` 保留登记和定位信息持久后，写本项收尾完成；含 `R` 的 `W` 保留。未发生接管且确实为空的工作区才可按身份删除空目录 | `clean` 不代表旧密码副本已删除。未知条目或身份不符不递归清空；保留故障与定位记录 |

`S` 增加磁盘占用，但使旧输入和候选验证绑定于私有冻结副本；它不是瞬时文件系统快照。磁盘预算至少覆盖旧原件、新候选、旧密文副本和可能的验证暂存；不假定压缩率或 clone 节省空间。复制过程中或接管后发现变化必须停止，不能悄悄以较新的源内容替代原任务。恢复时验证 `S/C` 的一致性可流式进行，不要求落盘明文。

按 R3 收敛方案，`S` 是本事务创建的可丢弃冻结副本，`R` 则是旧原件，迁移流程不自动删除。开始时必须告知保留位置、空间开销及旧密码仍有效；收尾登记后可将批次完成，不把保留 `R` 误计为清理失败。跨重启清理临时材料前仍须确认新版本与保留旧原件可定位；任何改动或未知占用均不自动清理。用户外部副本同样不在清理范围。

### 暂停、取消、回退与重试

- `queued` 到 `ready` 可在流处理的有界安全点暂停，停止新增项，保留 `O`；明确归属的未完成候选可以按记录清理，或者保留为待清理，但不能从未封尾的加密流字节偏移续写。再次执行使用新的 `attemptID`／候选槽位，旧尝试先进入可判定状态。
- 从接管意图开始，取消只设置“停止后续项”，不能在未知文件位置上宣布暂停成功。若尚未发布且 `R` 是已确认原对象、`O` 空缺、记录可写，则写 `restoreIntent` → 独占移动 `R → O` → 同步两个目录 → 核对身份 → 写 `restored`，然后暂停。恢复不要求旧文件内容仍等于快照，内容有变化时归还原对象并停止迁移，绝不销毁变化。
- `restoreIntent` 也有同样的崩溃窗口：`O` 为原对象且 `R` 缺失则核对后补记；`R` 为原对象且 `O` 空缺则在明确恢复动作中重试；其他布局停为冲突。不能覆盖占位文件，也不能在记录不可用时启动回退。
- 若新对象已在 `O`，优先核对并完成提交，再暂停；不自动撤销已经可用的新版本。若无法完整验证、缺密码或持久化失败，显示“提交结果待确认”，保留旧副本并暂停在 `needsRecovery`。
- 普通项目失败或离线会暂停整个批次，界面保留已提交数量与剩余清单；用户可明确选择继续其他可用项目，被跳过项仍待迁移。歧义提交／错误接管须先处理，不能带着未解决的原路径空缺继续另一项。
- “取消本次执行”保留任务；“回到旧密码”是另一个反向迁移需求，不在本轮自动恢复范围。混合批次不得直接删除任务或只把设置改回旧密码；用户可按 R9 的分类与提交协议结束为部分完成。仅当没有任何已提交／待确认项目、原件未接管或已持久归位、所有暂存已清理或移交有界义务清单且 pending 配置回退持久确认，才可标记为未执行而结束。

### 重启时的核对程序

启动只读取有界的私有清单／记录，显示待恢复，不自动访问用户目录、索要密码、续迁或清理。用户选择恢复后取得排他权，按记录重新授权精确父目录和私有工作区，确认其身份，然后仅检查 `O/S/C/R` 的固定槽位。卷未挂载不是“文件不存在”；权限失败不是“已删除”。任何未知占用或记录损坏都保留现场。

恢复判定先看合法持久意图，再看实际身份和密文内容，最后执行完整认证。下表用于继续迁移／提交的“旧／新”均指与本项记录绑定且通过对应密码完整验证的对象，不是看后缀、头部版本、时间戳或只试哪个密码能开头部；`∅` 指在授权有效、真实父目录已确认后确定不存在。

| 持久阶段与实际布局 | 判定与动作 |
| --- | --- |
| 接管意图前：`O=旧`，`R=∅`，`C` 缺失或未完成 | 原件未接管；重新验证源。已确认归属的未完成候选走清理，重新开始该项；保留失败阶段 |
| `ready/claimIntent`：`O=旧`，`R=∅`，`C=新` | 接管未发生或未持久生效；重新完整验证冻结输入及候选，用户继续后重新写接管意图，不能直接假定仍处于可发布状态 |
| `claimIntent/claimed/publishIntent`：`O=∅`，`R=旧`，`C=新` | 原件已接管、尚无持久新发布；重新完整验证并核对 `R/S/C` 后选择继续发布或按恢复意图归还旧原件。发布意图存在也不代表调用已成功 |
| `claimIntent/claimed`：`O=∅`，`R=旧`，`C` 缺失或验证失败 | 不用损坏候选；记录恢复意图并独占归还旧原件，停在失败／暂停，重新开始需新尝试 |
| `publishIntent/published`，尚无提交凭据：`O=新`，`C=∅`，`R=旧` | 发布已经发生；完整验证 `O` 并与冻结旧输入比较，重新确认数据／目录持久性，补写提交凭据。此处覆盖“替换成功、完成记录未落盘”的主要窗口 |
| 有提交凭据：`O=新`，`R` 已保留，`S` 仍在或已按意图清理 | 核对凭据与对象，完整验证后继续旧原件登记与临时清理，不重复迁移。`R` 缺失或改变不解释为自动清理成功，标记外部变化并保留记录 |
| 有提交凭据，但 `O=旧/∅/未知/验证失败` | 提交凭据与现场矛盾，停在 `needsRecovery`；保留所有副本，不撤销凭据、不自动重做或回滚，显示提交后的资源变化／损坏 |
| `O` 被无关对象占用，或 `R` 是误接管对象 | `conflict`；不读取无关内容、不覆盖／删除。误接管对象只能按身份保护的归还协议处理；原槽被占时保留并提示用户解决 |
| `O/C` 同时声称是新对象、旧对象同时出现在 `O/R`，或对象／摘要／记录关系不成立 | 非正常协议可产生的布局，保留证据，禁止凭文件名挑一份覆盖另一份 |
| 无提交凭据且 `R/S` 都缺失，只有 `O` 或 `C` 的新版本 | 无法重新证明与旧输入一致，不能自动补提交或删除它；保留可能唯一的可解版本，转人工恢复 |
| 记录不可读、未知版本、父目录替换、卷离线、密码缺失或错误 | 分别显示损坏／不支持／身份冲突／等待上线／等待密码；不继续迁移或清理。仅密码问题不阻止下述已确认原对象的归还；其他写入前置条件仍须满足 |

归还优先规则：若能确认原对象在 `R`、`O` 确定空缺、没有新发布或提交且记录可写，允许仅按对象身份执行 `restoreIntent` 协议；不要求密码正确、归档认证成功或内容等于 `S`，归还不读取／改写内容。此窄规则也适用于 `publishIntent` 已存在但尚未发布的场景，不能计为迁移完成。除该规则外，此表是白名单：未列出的布局不自行推演成成功，统一进入 `needsRecovery`。已有 `restoreIntent`／清理意图时应用对应的窄恢复规则。所有“补写”均须重新完成必要屏障，不能把“现在能读到”当作之前已经持久化。

### 批次完成与密码配置切换

批次主状态为 `planned → running ↔ paused/waiting → finalizing → completed`；按 R9 另有 `closingPartial → endedPartial/endedWithExceptions` 或 `closingCancelled → endedCancelled` 显式终止路径，另有 `needsRecovery`。`endedPartial/endedWithExceptions` 永不显示为全部完成。单项已迁移计数从提交凭据推导；清理进度另计，不因暂存清理失败把正确的新版本当成旧版本。离线／失败项仍在分母，当前阶段字节进度不持久写每个块，重启可显示“重新验证”，不承诺精确时间估算。

1. 开始先持久保存清单和 `beginIntent(g0, batchID, vOld, vNew)`，再按原配置代次 `g0` 条件更新配置为 `active=vOld/pending=vNew/batchID`，记录更新后代次 `gPending`；配置同步并读回后才写批次 `started(gPending)`。开始中断时，匹配的旧配置可按意图重试、已经写入的同批 pending 配置可补记，其他配置停为冲突；在 `started` 持久前不操作归档。旧／新版本均须绑定持久的密码验证依据及输入规则；其机制不能保存可直接解密归档的秘密，KDF／存储仍须安全复核。恢复时先验证输入与目标版本一致，不将原始密码存入任务。新的加密与再次换密码在混合期间被阻止；禁用菜单不能隐藏恢复入口。
2. 每项提交后，其登记版本更新为 `vNew`。登记更新失败可由提交凭据重建，不反向改动归档；配置全局激活不随第一项成功提前切换。
3. 正常全部完成路径要求所有冻结项目都有有效提交凭据、没有歧义提交；部分退出必须另走 R9，不能套用此完成判定。正常路径先写 `activateIntent(gPending, vNew, batchID, receipts)` 并持久保存，再按配置代次 `gPending` 条件更新 `active=vNew`、清除 pending，并记录新代次 `gFinal` 及该批激活标识。配置的文件／目录屏障完成后读回确认，再写 `activated(gFinal)`；若配置代次已被外部改变，不覆盖无关设置，转待恢复。这里的代次属于独立密码配置，不因更改主题等无关偏好递增。
4. 在配置写入前后崩溃：配置仍为匹配的旧代次／pending 时可核对后重试；配置已是该批次的新版本则核对后补记；其他代次或无法读取时停止。不得因配置仍旧而把已迁移文件重新用旧密码处理，也不得因配置已新就跳过未迁移项目。
5. 配置激活后显示“本次范围迁移完成，保留 N 份旧密码原件”，另列真正的临时清理失败。临时清理及旧原件登记完成后才将批次标记 `completed`；`R` 的保留不阻止完成。首版不自动压缩或删除事务控制记录，旧原件的最小定位／身份／版本登记一直保留，不因批次完成而删除工作区。

正常退出和更新重启：工作中先请求安全暂停，接管／发布及恢复阶段须得到可判定结果；不伪装成可立即退出。已经停在等待用户／上线状态时释放 busy guard，允许退出，保留持久记录。强制退出由上述崩溃流程处理，不依靠退出回调保证安全。

### 失败注入与待验证门槛

这是后续验证设计，本轮不运行探针或产品测试。测试必须调用最终生产事务路径，不能用构造状态替代实际中断测试。

| 注入位置／故障 | 必须观察到的结果 |
| --- | --- |
| 每个意图写入前、半写、写完未同步、同步返回失败；动作成功但结果事件未落盘 | 没有无意图破坏性动作；结果未知时先核对，计数不提前增加；坏记录原文保留 |
| `S/C` 创建、复制、解密晚期、加密封尾、候选完整验证 | `O` 保留；不完整候选永不发布；失败明文局限在私有暂存并有清理状态 |
| `O → R` 前／后及两目录同步之间，替换父目录／原件，原槽被并发占用 | 身份错误不读取、不销毁；原件归还只能独占；冲突不会覆盖无关对象 |
| `C → O` 前／后、目录同步后、`published`／提交凭据写入前后 | 重启分别覆盖未发布与已发布布局；完整认证后补提交或停止，不能重复加密新版本 |
| `restoreIntent`、恢复移动、恢复结果写入各窗口 | 原件最终在可确认槽位；恢复幂等，冲突保留；不会把新版本覆盖回旧版本 |
| 临时清理前后、目录同步失败、登记记录丢失、新归档被替换／损坏 | 已迁移数不倒退；旧原件绝不由迁移流程删除，未知对象不删除；收尾可重复核对 |
| 卷拔出、授权撤销、磁盘写满、记录容量用尽、旧／新密码错误、同批次双进程恢复 | 无权限不猜缺失、容量不足停在安全状态、密码失败不写文件、单写者成立 |
| 批次配置激活前后、混合版本取消／重启、离线项重现、配置丢失或代次冲突 | 每项真实密码版本与提交记录一致；不以设置推断文件版本；待迁移项不丢失 |

每个有文件系统副作用的步骤都要覆盖“调用成功但随后同步失败”，并分别验证捕获错误、进程终止、系统重启／存储持久性边界。SIGTERM 只覆盖进程级；没有经验证的掉电证据就明确保留该缺口。断言至少包括原件／无关对象保全、最终新旧密码矩阵、完整内容一致性、无公开部分明文、恢复幂等和进度准确，不只检查返回码。

实施前仍需确定：同卷与持久化能力支持矩阵、真实安全范围内的对象身份策略、日志限额及留存、归档结构验证接收器、用户对原路径暂时空缺的接受程度，以及密码输入／KDF 规则。以上待验证项不降低“私有暂存、完整验证、逐项可恢复迁移”的硬要求。

## 迁移方案审查（2026-10-19，静态审查）

结论：以下为最初审查发现；R1／R2／R3／R5／R7／R9 已在本节选择具体方案，状态为“设计已选、验证待做”，仍不能据此宣称运行安全。P1 表示可能导致密码版本失真、数据丢失或恢复流程无法继续，必须先收敛；P2 表示兼容性／生命周期边界未明确。这里记录的是根据设计推导的故障场景，不是新发现的运行时漏洞。文中已同步修正明确的规则矛盾；尚无具体机制或原生证据的项目仍保持 open，不用文字补充冒充验证通过。

| R5 / P1 验证链定义不完整 | 外层 AEA 长度一致、解密字节相同，并不证明内层归档没有多余数据或所有结构均已消费；候选使用新的 context 也可能遗漏不在解密流中的容器属性 | 限定 FileMint v1 子集，采用全流认证、标准 AA 重编码一致性及显式边界记录；资源限额和隔离验证待原生证明 |

### R1 收敛：原生 AEA 密码校验对象

**选择。** 不另造密码哈希协议。为每个密码版本保存一个小型、独立的 AEA password 校验对象，使用与该版本数据归档相同且经验证的原生 profile／KDF 配置；不用更低成本参数。校验对象不是数据密钥，不存私钥，也不允许仅凭校验成功跳过数据归档认证。它确实是离线猜测目标；不能宣称“加密了校验对象”就没有这个风险。

1. 版本绑定由 `versionID + inputPolicyID + cryptoPolicyID + bindingID + bindingCipherSHA256` 构成。`bindingID` 为随机标识；密文中是固定格式、固定256字节的校验载荷，包含用途标记 `FileMint.PasswordBinding.v1`、上述版本／策略／绑定标识及随机填充，其余字段禁止。载荷不含密码、密钥、文件路径或用户内容。外部只存非秘密标识及密文摘要。绑定密文上限64 KiB，解密载荷必须恰好256字节，拒绝尾随数据；同样在 R5 的隔离工作者中校验，但使用固定绑定载荷语法，不按用户归档 v1 条目流解析。
2. 输入策略 v1 固定为原始 UTF-8，不做 trim、Unicode 规范化或预哈希，不接受非法编码、NUL、控制字符及全空白；长度20–256字节来自当前 P0 边界，支持系统仍须逐版本验证。密码强度门槛沿用待安全复核的独立策略，不把字节数当强度。绑定对象记录输入策略，升级不得改变旧版本的解释。
3. 初次设置时创建绑定；迁移开始前复核 `vOld` 的已有绑定，再以用户两次确认的新密码创建 `vNew` 绑定，完整关闭、同步并重新打开认证，核对载荷及精确长度。拒绝按冻结规则得到的相同旧／新字节。创建和校验都在本次授权会话中完成；绑定持久后，批次清单冻结其密文摘要，再写开始意图及 pending 配置。
4. `vNew` 绑定一旦进入清单不可替换；重启后先匹配磁盘对象与清单摘要，再用当次输入完整解密绑定，精确核对所有载荷字段。旧密码输入同样验证 `vOld`。只有验证过的会话材料可送入相应解密／加密工作者；不允许将“密码已通过”的 Bool 与另一字符串组合。每项仍须旧归档认证、候选新密码认证及内容比对。
5. 绑定保留到所有引用该版本的活动任务结束，当前版本绑定继续用于新加密。重置或删配置不能重建活动批次的同名绑定；缺失、损坏、未知策略或标识不符一律 `bindingUnavailable`，停止迁移。没有旧绑定的外部 AEA 不直接纳入统一改密码，须走未来独立导入／登记流程，不能用当前输入给历史版本重新定名。

**失败处理。** 错误输入只返回版本密码不匹配，不创建候选；绑定写入／回读失败则不写 pending、不接管原件。开始意图已持久而 pending 未确认时，按批次开始恢复规则核对，不能换一个新绑定继续。暂停、锁屏或结束会话释放密码材料；明确恢复重新输入，不承诺进程内存绝对可擦除。纯对象归还仍不需要密码绑定成功。

**验收条件。** 相同版本跨重启只接受同一密码字节；错误新密码、交换旧／新绑定、替换为另一个合法绑定、同密码改密、NFC/NFD 混用、截断／尾随字节、载荷字段变化均在新候选写入前失败。至少验证“一项提交后重启再迁移另一项”以及“尚无任何成功项就重启”。在每个支持系统核对绑定与数据归档的实际 KDF 策略一致，绑定无更便宜的自定义快速校验路径；若原生配置无法读取或固定到可复核策略，则该系统不开放迁移，而不是仅凭相同 profile 名称认定等价。独立密码学复核仍是交付门槛。

### R2 收敛：预建固定记录槽与单链恢复

**选择。** 放弃变长文件中的连续追加及原地截尾修复。每次尝试使用固定大小的、预先创建并分配空间的记录槽文件；每个槽最多写一次有效记录，损坏槽永不复用。只访问清单登记的固定槽列表，不扫描用户目录。旧记录保留，读者按经过验证的前驱链取状态，不按文件时间或最大编号猜测成功。

**拟定首版限额。** 一个批次最多64项，每项最多3次尝试；每次尝试64个16 KiB槽，前32个供正常前进，后32个只供提交／归还／修复／停止记录。批次自身另有256个16 KiB槽；控制存储上限256 MiB，含清单、绑定、保留登记和所有旧尝试，以及R9结束预览、历史／清理义务和配置恢复记录。单条记录16 KiB以内，长书签及元数据只引用开始前已登记的有界对象。以上是拟定产品限制，不是性能结论；实现前状态图须证明正常前进及最坏有限恢复分支能装入，超限在接管前拒绝，不放大或裁剪记录。

| 步骤 | 具体规则 | 失败／崩溃处理 |
| --- | --- | --- |
| 建立槽池 | 在 `ready` 之前创建完整槽池，登记文件身份；对所有槽实际分配、写入初始化内容并同步文件／目录。批次收尾槽池在 `started` 前建立 | 任一步失败不接管；不把逻辑文件长度、稀疏文件或可用空间读数当分配证据 |
| 写一条记录 | 选择已登记的未用槽；写长度受限的完整帧，字段含 schema、批次／项目／尝试、物理槽号、逻辑序号、前驱槽及 SHA-256、事件、对象绑定、整帧 SHA-256；执行文件屏障并读回验证 | 返回失败就停止前进；不因为帧当前可读而假定先前持久成功。执行相应文件动作前必须有本次已确认持久的意图 |
| 推导权威状态 | 从清单绑定的根出发，仅接受身份匹配、校验正确、前驱一致且满足状态转换白名单的唯一链；派生索引仅作缓存，可重建 | 两个合法后继、链缺口、未知事件、已被后继引用的损坏槽均 `recordConflict`。不能直接选序号大的分支 |
| 处理末端损坏槽 | 保留其全部字节；只读核对 `O/S/C/R`。用户恢复后在全新保留槽写 `reconcile`，指向最后有效记录，并绑定被隔离槽号／原字节摘要和本次实际对象判定 | 仅允许无有效后继的末端损坏；中部损坏不自动修复。修复记录只能确认已有合法意图允许的实际结果，不得补造一条从未存在的发布意图；无法匹配时保持待人工恢复。`reconcile` 须完整持久后才允许新动作，原损坏槽仍保留 |
| 修复时再次中断 | 未持久的修复槽按同样末端损坏处理；新的修复记录列出本轮完整隔离集合，不能忽略先前损坏 | 多个合法修复分支或剩余保留槽不足则停止；不覆盖旧槽凑空间，不无界重试 |
| 进度与配置 | 单项提交凭据就是持久链中的 `committed` 记录；批次激活记录引用精确凭据摘要，普通偏好或缓存无权决定完成 | 跨卷不同步按既定意图／现场核对规则处理，不依靠全局原子写。整套旧状态被备份回滚仍不能靠哈希链检测，必须核对实际对象 |

记录槽不是必须原子写入的假设：撕裂写入按校验错误处理，真正的内容损坏仍停止。身份未知、读取失败或卷离线不能归类为“空槽”。初始化槽带固定无事件标识；只有匹配初始化内容和登记身份的槽可视为未用。正常恢复发现一条完整但先前同步结果未知的记录时，先核对其前驱与现场，重新完成所需屏障，再决定是否补结果或继续，不立即回退。

**容量与故障承诺。** 接管前要求正常槽够写下一意图，且保留槽足以完成至少一次归还或一次提交、一次核对修复及最终停止记录；批次池另须预留R9结束／配置激活的全部记录和至少一次恢复分支，不足时不得开始新的项目；字节进度不写控制槽。数据候选禁止使用控制槽。原生预分配和更强同步只是待验证手段：Apple 的历史手册区分了 [预分配与 F_FULLFSYNC](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fcntl.2.html)，不能据此认定当前 APFS 的写时复制、目录元数据及设备缓存都得到保证。首版拟限定本地 APFS，同卷工作区和目录持久性均须验证；失败不退回普通 flush 并继续。

已接管后遇到真实 ENOSPC、EIO、卷移除或屏障失败，即使还有逻辑空槽也不承诺一定能回退。若保留槽可持久写，则核对后按有意图的归还／提交到达安全点；若仍不可写，则保持原对象所在槽，进入 `storageBlocked`，不继续移动或清理。显示“旧原件保存在私有恢复区，原路径暂不可用”和精确恢复入口；空间／卷恢复后重新核对再继续。不会为腾空间自动删除 `R`、有效记录或唯一候选。**保证是故障时保全并停止，不是任意硬件故障下立即恢复原路径。**

**验收条件。** 穷举所有意图／结果写入、文件动作和同步之间的中断点；覆盖半帧、完整坏校验、合法但错前驱、两个合法后继、已登记槽被替换、合法记录可见但同步返回失败。修复连续中断两次后仍必须保留原始证据、最多接受一条合法链，并且重跑不重复发布。达到槽位／尝试／存储上限时不接管；实际写满要分别证明“仍可记录并归还”和“不可记录而停止保全”两条路径。文件系统与设备持久性不通过时该环境禁止迁移，不能把进程 SIGTERM 验证标为掉电验证。

### R3 收敛：保留旧原件，取消破坏性自动清理

**选择。** 首版迁移不会删除、截断、覆写或再次重加密 `R`。它在提交后转为明确登记的“旧密码原件”，继续位于同一私有工作区的原槽；不增加一次搬到公开备份名的竞态。这样取消了“检查旧原件后再删除”的动作，也不会因旧句柄继续写入而丢弃原对象。此选择改变收尾语义，但不增加真实文件操作，本轮只是方案。

- `committed → retainIntent → retained → cleaningTemporary → clean`：提交凭据持久后先记录保留意图，再把原 `R` 的身份、旧密码版本、位置与提交时摘要写入独立有界登记，读回并持久确认，最后记 `retained`。登记写入失败仍有 `R` 和提交凭据可恢复，停为待收尾，不删除它。保留登记成功、可丢弃暂存清理完成后批次可完成；该登记不是密码／数据备份，也不自动导出路径。
- 保留的是原对象，不是只保留 `S` 的字节副本；外部旧句柄之后的写入留在原对象上。发现内容或元数据变化标为“保留原件已变化”，保留且停止当次收尾，不再声称它与新归档等价；解除阻塞需要用户明确确认保留差异，绝不以自动删除解决。迁移不持续监控它，后续核对只发生在用户操作时。
- `R` 即使损坏、无法认证、被额外链接或不再与 `S` 相同，也不会被自动清理。新归档完整可用与“旧原件未变化”是两件事；前者不能授权删后者。工作区和保留登记没有自动到期时间，不因升级、关闭开关、清空历史或再次换密码删除。
- UI 在开始前和完成后明确：“当前归档改用新密码；保留的旧原件仍使用旧密码，需要自行保管。”显示保留数量和空间。首版不提供自动删除保留原件的按钮；可在授权后定位给用户自行处理。后续若需要应用内删除，必须成为独立需求，有明确并发模型和不可逆处置规则，不借当前迁移授权实现。
- 仅自动清理 FileMint 从空文件创建、身份已持久登记的 `S`、失败候选和本次验证暂存；不得清理 `R` 或登记外对象。操作通过固定父目录／工作区句柄，不跟随链接，复核所有者、类型、单链接、稳定身份及变化绑定；变化或不明条目一律保留。相同用户的恶意写入不能被0700权限阻断：此临时清理只支持无外部写入的私有工作区，主动敌对地替换私有槽位不属于保证范围。出现迹象就停止，不把检查后 unlink 说成原子的身份条件删除。
- App 内所有冲突操作（移动、删除、改名、迁移及恢复）共用资源排他控制，覆盖父目录和工作区祖先；独立解密读取活动 `O` 必须串行或返回忙碌。外部读取可继续，外部原件写入只提供检测及保留，不承诺获得全局一致快照。普通路径替换仍按独占接管后核对／窄归还规则处理，绝不覆盖无关占用。

**失败处理。** `R` 定位失败、父目录替换或卷离线时不能显示保留完成；保持提交凭据与待恢复登记，不动同名对象。登记中断可从提交凭据和原槽身份重建同一条登记，不制造第二份原件。`S` 清理失败只显示待清理；`R` 正常保留不算失败。新归档后来损坏时仍保留旧原件供用户恢复，但不自动覆盖新路径，也不宣称旧原件一定未被外部修改。

**验收条件。** 对原文件先持有写句柄，分别在接管后、候选验证后、提交后写入，再结束／重启任务：原对象和新写入都必须保留，迁移代码不得对 `R` 发出删除／截断；已检测差异必须可见。注入保留登记写入失败、卷离线、`R` 变更／缺失、临时槽替换：不能删未知对象或以临时清理成功推断旧原件已撤销。正常完成必须同时满足新密码可用、保留登记可恢复、旧副本提示准确；不得测试成“旧密码对所有副本失效”。

R6 的身份模型仍拆分稳定身份与变化戳；创建到首次身份登记的孤立对象窗口仍保守停止。R7 的字段白名单、私有候选应用和发布后读回均是提交门槛：保留 `R` 不能使新输出丢失 quarantine 等属性成为可接受行为。

### R5 收敛：限定格式、完整重编码比对与隔离验证

**选择。** 首版自动密码迁移只接受 `FileMint archive format v1`，加密仍使用原生 AEA password profile，不自制分块加密或 KDF。任意第三方 AEA、P0 的裸字节样本及没有 v1 结构的归档不直接原位迁移；未来导入转换须另行授权和验证。格式限制在接管前可见，不静默转换、删字段或降低认证能力。

**v1 格式边界。** 外层只接受已验证的 `hkdf_sha256_aesctr_hmac__scrypt__none`、LZFSE 和固定 `cryptoPolicyID`；不接受其他签名／收件密钥语义。`authData` 固定为空，不存版本、路径或用户标识；Apple 明确它是[可在解锁前读取的公开数据](https://developer.apple.com/documentation/applearchive/archiveencryptioncontext/authdata)。压缩块、校验与 padding 的允许值必须随 `cryptoPolicyID` 固定，不能用未记录的系统默认值；随机盐、nonce 和新容器标识由原生生成，不从旧容器复制密钥材料。若 SDK 无法暴露必要属性或证明所选策略，拒绝该格式／系统，不能猜测。

内层仍是标准 AppleArchive 条目流，只增加 FileMint 自己的结构约束：第一项固定为 `__filemint__/manifest`，最后一项固定为 `__filemint__/end`，两者为有界的普通数据条目；用户内容统一在 `payload/` 下，不能占用保留命名空间。manifest 记录格式版本、随机 archiveID、支持字段策略、用户顶层名称／类型、内容条目数与内容总字节数；end 重复 archiveID 和计数。两条记录在加密内部，迁移保持整个内层字节流不变，不嵌入密码版本。必须恰好一个首记录、声明的 N 个内容条目及一个尾记录；缺失、重复、额外记录或尾记录后的任意字节均拒绝。这是待固化的产品格式，当前 P0 不代表其已实现或兼容。

内容条目首版仅允许已列明的普通文件／目录及 `TYP/PAT/DAT/MOD/MTM/XAT` 字段组合；按类型规定必需字段、次数和 blob 长度，未知／重复字段拒绝。路径必须是唯一、相对、规范的 `payload/...`，拒绝空组件、点组件、绝对路径、符号／硬链接、名称冲突和父子类型矛盾。XAT 内部也须逐字段有界解析；资源叉等只有纳入策略且可完整验证才允许，不能将一个能读完的 blob 当成已验证元数据。

**验证管线，所有阶段在接管前完成：**

| 阶段 | 必须证明的事实 | 不足时的处理 |
| --- | --- | --- |
| V0 容器预检 | 固定输入对象，限制读取；检查支持 profile／策略；认证属性后 `containerSize == 固定源物理长度`，所有长度运算检查溢出 | 尾随垃圾、拼接 AEA、截断、未知属性或不支持策略直接拒绝；不裁剪输入后重试 |
| V1 全流认证 | 从头读到真实 EOF 并检查所有关闭错误；对整个解密输出计数与流式摘要；与认证的 `rawSize` 核对，始终受资源限额控制 | 原生只读到部分数据、关闭失败、超限或取消均失败；解码器说 EOF 不替代认证流 EOF |
| V2 严格结构及重编码 | 在有界管道中解析全部 AA 头和 blob；逐项验证 v1 语法，同时以原字段顺序／类型／值和原 blob 用标准 AA 编码器重编码到摘要接收器；重编码长度与摘要必须等于 V1 的完整解密流，且首尾／计数准确 | 原生解码器若忽略尾部或字段，重编码比较必须失败；任何非规范但原生可接受的编码也保守拒绝，不自动规范化 |
| V3 候选回读 | 旧输入 V0–V2 成功后，新候选完整封尾、同步，再独立执行 V0–V2；旧／新完整解密流长度及 SHA-256 一致，结构计数一致，容器策略符合允许改密的字段变化 | 任何不一致不进入 `ready`；同一原生实现的往返不是独立密码学证明 |
| V4 接管及提交绑定 | `ready` 绑定 `S/C` 对象、密文摘要、策略和本次验证会话；接管后的 `R` 与旧冻结输入完整核对；跨重启需重跑必要验证，不复用内存摘要 | 源变化归还或停止；候选变化重做。只有已通过全部验证的候选可发布，旧原件按 R3 保留 |

V2 选用标准[头部表示](https://developer.apple.com/documentation/applearchive/archiveheader)、`readHeader`／`readBlob` 和 encode API，不自行实现新的加密格式。重编码不是“修复归档”：接收器只计数和摘要，不输出替代归档。标准编码器必须在允许子集上生成完全一致的字节流；若特定系统做了不可控制的转换，拒绝该子集／系统，不能放宽成只比解出来的几个文件。合法结尾只能是 v1 尾记录之后的真实 EOF，首版不允许额外内层 padding。即使解码器读前缓冲吞了尾部，V1 的全流计数／摘要仍包括它，V2 不得因此免检。

**资源与取消。** 拟定 v1 限额：单归档解密流64 GiB、内容条目100,000、路径深度64、路径UTF-8总长4 KiB、单头64 KiB、首尾记录各64 KiB、单XAT 1 MiB／全部XAT 64 MiB；读写块1 MiB、队列最多4块、最多2工作线程。计数和长度先做检查再分配，摘要及重编码只使用有界内存；大文件不整体读入。限额属于设计初值，须经测试调整并版本化，不能在超限后悄悄跳项。

原生解析／KDF／解压放入独立的沙盒验证工作者；它只接收本次固定的只读源和仅能写候选的句柄，不持有发布、删除原件、记录提交或扩大目录权限的能力。密码通过本次私有 IPC 在内存传递，不放 argv、环境变量、文件或日志；正常结束释放。父进程负责流量／内存／无进展监测：工作者内存预算512 MiB，无有效字节或阶段进展30秒即终止为超限；用户取消后合作停止，2秒未退出则终止工作者并将候选标为未验证。只有工作者已退出或关闭所有输出句柄后，才允许父进程清理候选。单调有效计数才算进展，心跳不重置限额。严格内存上限和终止延迟须由实际平台机制验证，不能把轮询 RSS 写成硬上限；无法满足就阻止该环境开放功能，不用主进程内无界解析回退。

**失败处理。** V0–V3 的解析错误、资源超限、工作者崩溃、IPC断开、认证错误及关闭错误统一不发布，保留 `O`；仅清理确认归属且无写者的候选，清理失败留可恢复记录。工作者声称成功必须与父进程登记的输入／候选身份、实际结束及输出关闭一致；不接受其他尝试的过期消息。归档格式错误不自动改用宽松解析器。v1 内容读取与真正解密到目录共用严格验证条件，后者仍只写私有暂存后发布。

**验收条件。** 构造外层追加／截断／等长篡改，内层附加随机字节、第二个完整归档、重复字段、额外合法条目、错误首尾／计数、重复及逃逸路径、XAT内截断、长度溢出；所有情况必须在接管前失败。专门模拟原生解码器提前报 EOF 或忽略字段，V1/V2比较必须发现差异；规范空文件、空目录、Unicode名称和支持元数据须通过。覆盖每项限额边界及超1、阻塞KDF／解压、无进展、工作者崩溃、取消和延迟写句柄关闭；不允许父进程发布或提前清理。正常旧／新回读验证必须完整消费原输入，保持相同内层字节，且通过独立已知内容清单核验；未达到这些条件时不启用自动迁移。

### R7 收敛：外层元数据 v1 白名单与提交门槛

**选择。** 本节只处理“加密归档文件自身”的元数据，不改变 R5 加密内部的用户文件元数据。定义独立 `outerMetadataPolicyID=v1`；拒绝不能完整读取、不能按规则保留或含未知属性的项目，不用“旧原件还在”代替新输出正确性。首版范围有意保守，不能被宣传为任意 Finder 属性／权限无损迁移。

Apple 的 [URL 资源键](https://developer.apple.com/documentation/foundation/urlresourcekey)提供安全、大小和身份等属性接口，[quarantine 属性](https://developer.apple.com/documentation/foundation/urlresourcekey/quarantinepropertieskey)也有独立表示；接口存在不证明一次通用复制就完整保留所有属性。本方案要求按字段读取、应用与验证，不把 `copyItem` 或 `COPYFILE_ALL` 的成功返回作为元数据验收。

| 字段 | 首版规则 | 拒绝／变化处理 |
| --- | --- | --- |
| 文件类型、名称、对象身份 | 只接受当前用户拥有、单链接的普通文件；保持原路径组件的精确拼写。新密文有新对象身份，旧对象保留为 `R` | 链接、非普通文件、别名／包、父目录替换或所有者不是当前用户均拒绝；不更改所有权以取得资格 |
| POSIX mode、UID/GID | 保留 UID/GID 与允许的权限位。必须含所有者读权限；禁止任何执行位、setuid/setgid/sticky、组／其他用户写权限。所有者写、组／其他用户读权限按原值保留 | 无法在无需提权的前提下设置并精确读回 GID／mode 即拒绝；不自动收紧／扩大为一个“差不多”的权限集合 |
| ACL | 源必须确认无扩展 ACL；新 `W/C` 也须确认无扩展 ACL（包括继承 ACL） | 非空 ACL、ACL 不可读或候选因继承产生 ACL 均拒绝；不清除源 ACL，不靠 chmod 假定 ACL 已消失 |
| BSD flags | v1 只接受 flags 为0的源，候选同样为0 | 任一用户／系统不可变、append-only、hidden、压缩或其他 flag 均拒绝；不清除这些标志后继续 |
| 创建时间、内容修改时间 | 保留源的原生精度值；写完密文和 xattr 后应用，再同步、读回；在允许系统上要求相等 | 精度损失、设置被拒绝或发布后不一致均不能提交；不将当前时间冒充保留成功 |
| 访问时间、状态变更时间 | 不承诺保留；读取和元数据操作造成的系统变化不视为内容变更。迁移摘要说明这两类时间可能改变 | 不为恢复访问时间再写旧原件；不能以忽略这些时间为由忽略内容、mtime、权限或属性变化 |
| `com.apple.quarantine` | 有则按原始有界字节保留，无则记录缺失；不经 Foundation 字典转换丢字段，不清除或伪造下载来源 | 候选已带不同 quarantine，或源在处理中新增／改变 quarantine，停止；不删掉候选新增的安全标记来凑相等 |
| Finder tags：`com.apple.metadata:_kMDItemUserTags` | 按原始属性字节保留；缺失与空值区分，不重排、重命名或把标签文字写日志 | 读取／应用／回读不一致即拒绝；不通过 Finder UI 或其他进程补写 |
| 来源：`com.apple.metadata:kMDItemWhereFroms` | 按原始有界字节保留，不访问其中 URL，不把它当成可信来源证明 | 值超限、变更或无法回读则拒绝，不静默丢弃 |
| FinderInfo、外层资源叉及其他 xattr | v1 不接受这三项白名单以外的任何 xattr，包括 `com.apple.FinderInfo`、`com.apple.ResourceFork`、provenance、decmpfs 和未知属性；即使值为空也拒绝 | 明确提示“不支持该外层元数据”，不删除后重试。内层资源叉是否受支持仍由 R5 单独规定 |
| 大小、密文摘要、分配大小、inode／文件 ID | 新密文大小与摘要重新记录；分配大小和对象 ID自然改变，不按旧值恢复 | 这些变化不能成为放过数据不一致的理由；对应内容仍须通过 R5 |

xattr 名单读取最多32项、名称各不超过255 UTF-8字节、允许的单值不超过64 KiB／合计192 KiB；超限或读两次集合／值不一致即停止，不遍历相邻文件，也不重试到“碰巧稳定”。属性缺失必须有明确成功查询结果；权限错误或读失败不是缺失。以上是拟定输入上限，须与实际受支持样本验证，不代表平台上限。

**冻结、应用与验证顺序。**

1. 在打开并固定 `O` 后读取稳定身份和元数据快照 `M0`，校验白名单；数据读写期间不改源权限、xattr 或时间。记录策略 ID、允许的基本属性和整体元数据摘要；标签／来源／quarantine 原字节仅在内存中处理，普通日志与诊断不记录。摘要只是变更绑定，不是认证证明。
2. `S/C` 新建时为0600，`W` 为0700且无扩展 ACL，整个验证过程中保持私有。先完成 R5 内容验证并关闭全部写密文句柄；再在 `W` 内对**密文候选**应用允许 xattr、UID/GID及最终 mode，最后设置创建时间与 mtime。源允许的组／其他读位只可在这一密文候选阶段恢复，`W` 仍阻挡公开访问；明文暂存始终保持私有，不继承这套外层权限。
3. 应用不是一次盲目批量复制：每个调用错误都停止，不吞错误后补写完成。应用后重新枚举候选的完整 xattr 集合、ACL、flags、UID/GID、mode及保留时间，与 `M0` 精确比较；候选出现未知／新增安全属性也停止，不能删掉它。完成数据／元数据屏障后记录 `metadataPrepared`，绑定 `M0`、候选身份及密文摘要，再进入 `ready`。
4. 接管前重读源快照；接管后对 `R` 再核对。稳定身份、内容、权限或保留字段变化都使候选失效；在尚未发布时按窄归还协议归还原对象，不把新变化覆盖成 `M0`。rename 自身可改变状态变更时间，它不进入相等判定；其他例外不能自行增加。
5. `C → O` 后、写提交凭据前再读回最终 `O` 的元数据，确认发布没有引入继承差异或属性丢失。凭据同时引用 `metadataPrepared` 与发布后读回摘要。读回失败／不一致进入 `publishedMetadataMismatch`，不计迁移完成，不自动修补公开 `O` 或覆盖回旧文件；`R` 保留，用户可独立解密新对象，但事务需先解决异常。重启后只有实际对象完整满足已冻结契约才可补提交。

跨重启恢复所需的属性原值优先从身份已确认的 `O` 或 `R` 重读并与持久摘要比对；不从标签摘要猜值，也不把候选中的属性反过来当成源快照。无法重建 `M0` 时停止补提交，但仍可按身份执行不改内容的原件归还。权限应用后需保持验证与同步可执行；若允许的只读 mode 在目标系统上无法完成顺序，则该 mode 不予支持，不能临时放宽源文件权限。

**失败处理。** `metadataUnsupported`／`metadataUnstable`／`metadataApplyFailed` 在接管前保持 `O`，只处理本次候选；接管后但未发布则尽可能有日志地归还，失败保留现场；发布后异常不自动移动任何版本。所有错误保留具体阶段，UI 可显示属性类别，不输出属性值或完整路径到日志。通过额外授权也不能绕过“不支持”的字段策略。

**验收条件。** 对允许的各 mode、UID/GID、纳秒时间、缺失／空值／非空 tags与来源及 quarantine 分别真实读回；验证最终 `O` 与 `M0` 相等、新旧内容可解、旧原件未被修改。覆盖ACL继承、其他所有者、所有不支持flags／xattr、外层资源叉、精度丢失、属性读失败、设置部分成功、源前后增删属性及发布后属性变化；不得出现“返回成功但属性丢失”。在每个字段应用和 `metadataPrepared`／发布后读回之间终止进程，恢复须重复核对，不跳过元数据门槛。此处列出的原生行为均待验证。

### R8：收尾证据与后续批次

- 提交凭据只证明其记录时刻；正常全部完成的激活前，对冻结清单精确项目重新核对身份／密文／元数据绑定及所需完整验证，离线、替换或认证失败阻止**全部完成**。逐项核对不构成跨卷原子快照。部分退出则按 R9 保留历史提交事实与当前不可确认状态，不能套用全部完成文案。
- 允许启动下一次改密的终态为 `completed`、`endedPartial`、`endedWithExceptions`、`endedCancelled`，且没有未决原件移动、未知发布或活动工作者；暂存义务和历史旧版本继续登记，不随新批次重置。后续清理只能处理其登记的私有临时对象，不能用上一批记录清理新批次的 `O`。

### R9 收敛：部分退出、配置提交与缺失恢复

**选择。** “暂停”保留活动迁移及限制；“结束本次迁移”是一个独立的持久终止操作。它不撤销已提交项、不删除旧原件、不缩小历史清单，也不把未处理项当成功。结束后可恢复今后新加密能力，但历史归档仍按各自密码版本处理。整个流程有明确结果页，当前方案文档的讨论不是实际执行授权。

#### 退出前的项目分类

| 分类 | 必须有的证据 | 能否结束／如何记录 |
| --- | --- | --- |
| M 已提交且已收尾 | 合法提交凭据、保留登记及临时清理结果／移交记录，没有未知发布；可用时重新核对当前状态 | 可以；保留 `vNew` 和提交事实。当前离线／已被外部改动另设标记，不把旧凭据显示为当前已验证 |
| U 未迁移 | 从未存在接管意图，或原件已有合法 `restored` 结果；没有待定的文件动作 | 可以；保留原版本或“尚未认证的登记版本”，记录离线／无权限／格式不支持／主动停止等原因，不声称文件现在仍存在 |
| T 可延期暂存 | 明确归属的 `S/C` 或已创建未使用的槽，所有工作者和写句柄已结束，原件位置已确定，没有仍需这些对象判定的动作 | 可以移交独立清理义务清单；清单保留身份、策略／版本引用和失败原因，不自动到期。T是项目附属状态，不重复计入总数 |
| A 动作结果未决 | `claimIntent/publishIntent/restoreIntent` 尚未与现场闭合，`O` 空缺待恢复、误接管未归还、日志冲突、已发布但元数据不合格等 | 不可结束；保持 `needsRecovery`。卷离线或用户称已自行处理，均不能代替协议所需证据 |

结束前停止调度、结束所有验证工作者并取得批次排他权；先处理 A，再冻结 M/U/T 列表及其所引用的精确记录摘要。处于离线卷但**从未接管**的 U 可以延期，不需要扫描或虚构源存在；曾接管且缺少确定结果的离线项仍为 A。M 的当前状态无法重查时标为“历史已提交，当前未确认”，不会因此丢失凭据或被自动迁移第二次。尚未持久完成旧原件登记的提交项须先据记录建立登记或恢复，不能当作普通 T 丢开。

#### 用户流程与持久化顺序

结果预览固定显示“已提交 M / 原范围 N、未迁移 U、当前不可确认数、保留旧原件数、临时清理义务数”，逐项保留版本／原因。明确说明：已迁移项不回退；旧归档和保留原件仍需旧密码；部分结束不会让未知副本换密码。用户确认的是这份冻结预览，预览代次变化必须重新生成，不能沿用旧确认。

| 阶段 | 顺序 | 失败／恢复 |
| --- | --- | --- |
| 1 `closePrepared` | 确认无 A、工作者已结束；检查 R2 槽位和存储额度足够；持久保存 M/U/T 快照、清单总数、预览摘要及待结束类型 | 写入失败仍是暂停；不更改 active、不释放迁移限制、不丢项目 |
| 2 建立后续登记 | 将 U 写入 `legacyPending`、T写入延期义务，保留 M 的版本和 R 定位；绑定两个版本的校验对象引用，完成有界写入、读回与屏障 | 任一步失败留在 closing；不能先删原任务或释放引用。登记对象使用原项目 ID 和来源批次去重 |
| 3 `partialActivateIntent` 或 `cancelIntent` | M非空：用R1验证 `vNew` 密码，写带 M/U/T 摘要、目标 `active=vNew` 及期望配置代次的意图。M为空：目标保持 `active=vOld`，结束类型为未执行，不要求为归还输入密码 | 旧／新密码遗忘不会被重置绕过；M非空却无法验证目标绑定时停在 closing。M为空也不得存在A |
| 4 条件更新配置 | 按匹配的 pending／配置代次更新 active，清除本批活动指针，保留终止批次 ID、结束类型和全部后续登记引用；同步并读回 | 调用失败先核对。目标配置已写入则补后续记录；仍旧且匹配则可重试；其他代次冲突停住，不改无关偏好 |
| 5 `endedPartial`／`endedWithExceptions`／`endedCancelled` | 持久写入终止凭据，引用配置新代次与M/U/T摘要；最终读回后才释放操作限制并展示终态 | 配置已更新而凭据未写时，启动从 closing 意图识别未完成收尾，继续阻止新迁移；不得仅因 pending 已空就认为已结束 |

普通换密码批次（`kind=rotate`）在 M非空且 U非空时使用 `endedPartial`。U为空且当前全部核对通过时走正常完成；若全部已有合法提交／保留登记，但存在提交后外部变化或离线、导致当前无法重验，则可经同一显式确认和持久协议结束为 `endedWithExceptions`，显示“历史已提交 N/N，当前不可确认 E项”，不表示全部当前有效。此例外仍禁止A，不能容纳尚未提交的元数据失败。M为空时即使有临时材料也按 `endedCancelled` 保持旧active。M/U必须无重叠且并集为原清单，不删除无法定位的项目。配置写入前后及终止凭据失败均按上述单一意图恢复，用户重复点击不重复生成批次或登记。

终止后新加密使用 active 版本；所有历史U仍显示“未迁移”，不计为清理完成。以后用户明确选择一个历史U时，重新授权／捕获身份、验证其登记版本绑定和实际完整认证；使用新的 `catchUp` 批次迁移到**当时** active 的绑定，旧终态不可重新打开。`kind=catchUp` 不新建密码版本，源版本为历史版本、目标绑定为当前active；开始配置保留active不变，只登记独立的活动迁移指针，不写“active=历史源版本”或创建pending密码。它仍完整走单项事务与同样的M/U/A分类；任何完成／部分结束／未执行终态都保持原active，只清除匹配的活动指针、更新项目及历史登记。开始后禁止另一次改密，发现active代次改变则停止；不能套用rotate的M为空回旧密码规则。多个历史源版本拆成不同批次，不暗中试密码。

下一次改密码仅覆盖当前active版本的已登记归档，开始页必须另列历史U和所有保留旧原件，说明它们不在本次范围；不通过删除它们实现“一个密码全部统一”。延期T只允许用户明确重试清理，未确认归属的材料不自动删除；义务／历史登记达到存储限额则停止新任务，保留记录并提示导出或后续管理，不用丢弃历史解锁配额。

#### 配置丢失：按剩余证据分级

普通偏好、密码配置、事务索引／清单／记录槽、版本绑定和归档是不同资源。恢复默认主题等偏好不能重置密码状态；密码配置存在但损坏、未知版本或不可读时，保留原字节并进入恢复页，不覆盖成初次启用。启动仅查询已知私有存储和已有直接引用，不扫描用户目录或全盘寻找密文。

| 剩余证据 | 允许的恢复 | 禁止推断 |
| --- | --- | --- |
| 仅普通偏好丢失；密码配置与任务完好 | 按现有startup契约处理普通偏好，密码与任务保持；不重新设主密码 | 不能把一般设置重置当作迁移取消 |
| 密码配置丢失／损坏，但清单、唯一有效记录链、终态及所需绑定完整 | 用户明确选择“恢复密码配置”后，先只读还原预览；依据 started／activate／partial结束记录推导active、pending和历史引用，复核绑定。若有未决用户文件动作，先保留其活动状态而非认定完成 | 不按最近文件时间、最多可解项目或任意一个归档推测当前active |
| 事务索引缺失，但密码配置保留完整批次ID、清单／根记录摘要与直接存储引用 | 只打开这些固定引用，验证清单、记录链和绑定；可重建派生索引 | 不能枚举任意目录挑一个“最新任务”，不能把索引缺失当作任务已结束 |
| 配置存在而所引用的清单／记录链损坏或缺失 | 保持active的历史记录但阻止新的统一迁移；可按密码独立解密明确选中的归档。仅可从匹配的完整备份恢复缺失链，再核对实际对象 | 不能清除pending绕过，也不能从文件大小／路径或新密码能解一个文件补造提交凭据 |
| 版本绑定丢失／损坏，归档仍可解 | 正确密码可通过独立完整解密读取归档；迁移绑定只能从与清单摘要一致的备份恢复 | 能解密文件不证明对应旧versionID；不能用当次密码创建同ID替代绑定或补记历史完成 |
| 所有控制元数据丢失，只有用户手动选择的归档／工作区 | 进入只读救援：固定选择对象，完整验证，报告每份是否可解；可另行明确请求把明文输出到新的私有暂存后独占发布 | 工作区名、内嵌archiveID或未验证的外部记录不授权把R移回O、不证明新旧顺序、不授权删除重复副本 |
| 全部证据都不可访问，或完整旧备份与现场矛盾 | 显示无法自动恢复；保留现场，等待卷／授权／完整证据。只有用户明确选择新建独立保护配置才创建新存储epoch和新版本 | 不承诺自动识别“从未设置”和“全部记录丢失”，不扫描补齐、不让新配置解开旧密文 |

为支持第二、三行，开始配置和清单需双向记录批次ID、根记录／绑定摘要及固定存储引用；它们不是跨存储事务，仍按意图先行与现场核对恢复。元数据哈希链只检查一致性，不证明抵御恶意同用户篡改或完整备份回滚；所有外部定位信息须重新授权、核对实际对象。未执行的用户文件动作不会仅因导入一份形似合法的记录就自动执行。只读预览及恢复配置中的版本引用不要求解密所有归档，但必须核对绑定对象与既有摘要；真正开始加密／续迁仍须重新通过R1密码验证。恢复配置不会生成已解锁会话。

**配置重建顺序。** 恢复先只读计算并展示 `recoveryPlan`（来源文件摘要、证据等级、推导状态、不可确认项）。用户确认后，在独立R2恢复槽池写 `configRestoreIntent`，绑定旧配置缺失状态或损坏文件的精确身份／摘要，创建新的恢复配置候选并同步。保留损坏原文；发布前再次核对原槽，只有仍匹配的缺失／损坏对象才允许按有日志的独占接管／发布协议安装候选，有新占用则停止。读回并同步后记 `configRestored`，再恢复原任务入口；只重建配置不自动开始文件迁移。配置恢复本身中断时按已登记的候选／旧配置槽位核对，不覆盖用户刚修复的配置。不能为修配置修改其他偏好、密码或版本绑定。

新建独立保护配置属于明确的用户选择：先展示旧资源未恢复、旧密码仍需要、未知恢复区不会被自动清理；为新配置生成全新epoch／versionID，旧材料保留且不重新贴标。若已有可读记录证明存在A类未决动作，首版先要求解决A，不允许用新epoch逃避原件归还。没有任何可识别记录时，系统无法保证未知工作区已被恢复，应如实提示；仅允许新的显式选择操作，不恢复旧自动任务。来自救援的归档如以后要纳入统一管理，走独立的“新建加密副本并登记”流程，不原位接管无证据旧文件，也不伪造旧任务完成。

**退出与恢复验收条件。**

1. 分别覆盖 M=0、U=0、M/U均非空，离线U、原件已归还U、带T及带A；只允许符合证据的终态，A存在时不能部分退出，M/U计数恒等原清单。
2. 在后续登记、结束意图、配置写入／同步、终止凭据各窗口中断；重启后active、pending、历史版本和允许新加密状态一致，重复退出幂等，不删除R或丢U/T。
3. 部分退出后新加密使用vNew，历史U仍用原版本；下一次改密不悄悄迁移／抹掉历史U；catchUp使用当时active绑定，错密码／版本不符不写候选。
4. 覆盖部分退出时新密码遗忘、绑定缺失、槽位不足、配置代次冲突、旧副本离线及可见新对象已变化；均不得借“结束”误报全部成功或跳过未决动作。
5. 逐个删除／损坏偏好、密码配置、索引、清单、末端／中部记录及绑定，并测试全部控制元数据丢失；只允许上表所列恢复等级，不猜测、扫描或自动覆盖。恢复配置的候选／旧槽位中断也要独立验证。
6. 从旧备份恢复、选择同名不同身份文件、导入无关任务记录或中途出现新配置；必须核对冲突并保留原文，不能按时间戳选择。记录全失时只能明确新建独立配置或只读救援，不能声称恢复历史密码管理。

### 新增验收场景（未执行）

1. 第1项提交后重启，输入不同但有效长度的新密码；必须在写第2项前拒绝。覆盖同密码、Unicode 规则变化及密码绑定记录丢失。
2. 接管后耗尽普通日志空间、写入半帧、出现完整坏校验帧、修复索引切换时崩溃；分别证明不错误续写、不遗失提交、不无意图回退。
3. `R` 完成认证后经旧描述符改变内容／外层元数据，以及清理检查后替换槽位；不得删掉变化或无关对象。首版必须证明不会自动删除 `R`，临时槽位的未知占用则保留并停止。
4. `O` 空缺、`R` 是原对象但内容损坏或忘记密码；应能通过受控归还恢复原目录项，不能继续发布或计为迁移成功。
5. 外层合法而内层含额外数据／第二归档，容器带未知属性，超大元数据／解压输出；必须在接管前拒绝或有界终止，不能静默丢失语义。
6. `W/S/C` 创建后、首次身份登记前崩溃；不能误认或清理同名外部对象，明确残留与人工恢复边界。
7. 最后一项结束前替换第一项、激活后清理未完就请求再换密码、永久丢失冻结项目、配置与事务索引恢复到旧备份；不能把旧记录直接当成当前成功或启动新批覆盖旧证据。
