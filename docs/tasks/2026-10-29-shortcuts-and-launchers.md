## Objective and scope

让用户从 macOS 快捷指令、Raycast 或通用 URL，把名称、模板、文本和保存位置带入 FileMint，检查后创建文件。外部工具负责发起，FileMint 负责草稿、授权、校验与写入。Alfred 的导出、安装、真实入口验收及宣传移至二期，不属于本期交付。

本次目标版本将此功能作为核心宣传点：首次接入能独立完成，日常固定工作流只填一个变化项，草稿出现后能立即看懂并确认。三项体验与入口正确性共同决定是否完成，不能把入门引导、草稿体验或真实示例留到后续版本，再将本版标为完整交付。对外定位围绕“从常用工具带入名称与内容，在 FileMint 确认后创建”，不承诺静默自动化。

用户于 2026-10-31 明确纠正最低版本范围：FileMint 整体继续支持 macOS 13.0，只有快捷指令与启动器接入要求 macOS 13.3；不满足时显示禁用状态且拒绝调用，不提高主 App、Finder 扩展、CorePackage 或安装/更新的最低版本。功能仍用单一 ForegroundContinuable 路线，不增加低系统回退。历史 P0 与产品证据保留原构建归属，不能据此宣称 macOS 13.0/13.3 实机运行通过。

首个完整版本包括：

- 原生快捷指令动作“打开文件草稿”和“显示快捷搜索”。
- 版本化的公开草稿 URL，以及仅负责唤起现有快捷搜索的 URL。

### 核心产品决定

1. **双入口、同一执行链。** 快捷指令用 App Intents；Raycast 和通用链接用受控 URL。两者转成同一份有类型的草稿请求，避免按入口复制创建逻辑。
2. **只打开草稿。** 外部调用不产生用户文件，最终写入始终由 FileMint 的“创建”按钮触发。
3. **已有草稿始终优先。** 新请求不能改写、合并或替换它，也不暗中排队；明确反馈“新请求未打开”。
4. **位置与权限分开。** 路径、收藏 ID、模板 ID 和请求 ID 都不是授权凭据；保存前沿用原生目录授权。
5. **操作结果说实话。** “系统接收 URL”“FileMint 已打开草稿”“文件已创建”是三件事。启动器不能把第一件显示成第三件。
6. **正常路径短，复杂选项渐进出现。** 同设备、模板/目录配置与访问仍有效时，复用已配置的动作或已导入命令，日常只输入名称 → FileMint 检查 → 创建；授权失效、目录/模板变化走明确恢复流程，不承诺一次接入永久有效。
7. **体验与能力一起交付。** 本版必须通过首次接入、日常单项输入、草稿第一眼三项验收，并取得真实入口与结果证据；只有接口可用或导出成功不算完成。

## 2. 用户场景与操作成本

| 场景 | 用户路径 | 正常完成成本 |
| --- | --- | --- |
| 快速新建项目笔记 | Raycast 输入预设命令及文件名 → FileMint 草稿 → 创建 | 一个命令 + 一次创建确认 |
| 工作流生成文本 | 快捷指令组织文本 → 打开 FileMint 草稿 → 检查文本与位置 → 创建 | 不复制、不手工拼链接 |
| 固定模板与常用目录 | 运行已配置的快捷指令或 Raycast 命令并填写名称 → 预选模板及项目目录 → 创建 | 每次只填变化的名称 |
| 临时位置 | 外部传入目录建议 → 草稿显示完整目标 → 创建时按需授权 | 有效访问可复用，缺少访问才请求 |
| 唤起统一搜索 | 启动器执行“显示 FileMint 快捷搜索” | 一次命令，现有查询可恢复 |
| 草稿冲突 | 新调用到达 → 聚焦旧草稿并提示未接收 → 用户完成/取消后重试 | 不丢原文，不产生隐形第二份草稿 |

全局快捷键开关只控制 FileMint 自己注册的组合键。关闭它、隐藏菜单栏或关闭设置，均不禁止这些明确的外部调用。真正退出 App 后，由系统调用按需启动主 App。

### 2.1 本版必须交付的三个入门场景

| 场景 | 首次配置 | 日常变化项 | 用户应看到的结果 |
| --- | --- | --- | --- |
| 新建项目笔记 | 选择现有启用文本模板和项目目录；在所选工具中添加动作或导入命令 | 只填笔记名称 | 正确名称、精确模板、模板正文和目标位置已填好，确认后创建 |
| 保存工作流生成的文本 | 在快捷指令中将上游文本接到 FileMint 原生动作，配置模板/目录及固定或已有变量提供的名称 | 只有上游文本变化，FileMint 不再要求手工输入第二项 | 文本原样进入草稿，不复制粘贴、不重复选目录；仍由用户确认创建 |
| 显示快捷搜索 | 添加原生动作或导入所选启动器命令 | 无参数 | 直接出现可输入的现有搜索，保留原有查询恢复与模态保护 |

“新建项目笔记”优先展示现有启用 Markdown 模板；没有可用项时让用户显式选择其他启用文本模板或进入模板设置，不自动启用模板。示例使用合成文本和用户明确选择的位置，不硬编码开发者路径，不自动创建目录/收藏。以上是同一入口的引导配置，不增加另一套模板系统或持久化敏感正文预设库。

### 2.2 单项输入的适用边界

主宣传路径为“模板和位置配置好，日常只填名称，确认后创建”。默认入门命令不再追问后缀、模板、正文和目录；需要多项输入的高级配置仍可使用，但不作为默认演示。快捷指令文本场景直接消费上游结果，名称沿用已配置值或上游已有变量，不额外弹出名称输入。

日常验收使用用户通过既有设置明确授权、且本次仍有有效写访问的目录；导出的路径/收藏 ID 不产生新授权。首次授权、临时目录和访问撤销必须各自验收与说明，不能为了减少步骤把临时访问偷偷持久化。配置有效时不得重复要求授权；访问确已失效时保留草稿并引导恢复，不静默换目录。对同一输入保留既有重名处理、真实写入回执与创建后动作。

## 3. 总体架构与职责

```text
快捷指令 App Intent ─┐
Raycast 脚本 → URL ──┼→ 解析 / 规范化 / 限额
通用 URL ────────────┘       ↓
                     ExternalDraftRequest
                             ↓
                  主 App 原子接收与生命周期协调
                             ↓
                    单一原生创建草稿面板
                             ↓ 用户点击创建
                    目录访问与身份复核
                             ↓
                  现有 FileCreationService
                             ↓
                  写入回执 / 原有创建后动作
```

### 3.1 最小组件

| 层 | 拟议职责 | 明确不做 |
| --- | --- | --- |
| Core `ExternalDraftRequest` / `ExternalDraftRoute` | 有类型数据、严格 URL 解析、字段关系、内容来源、字节限额和错误码 | 不显示 UI、不访问 Finder、不申请权限 |
| App Intents adapter | 原生参数与实体查询，映射请求，返回草稿接收结果 | 不另写文件、不把正文转进 URL |
| 主 App admission coordinator | MainActor 上原子判断准备中/模态/草稿/写入状态；建立会话和临时访问归属 | 不保存正文、不后台排队、不调用私有快速创建 |
| SharedUI 草稿种子 | 一次性应用文件名、格式、文本、目录建议与提示；输出现有创建请求 | 不读取主 App 全局设置模型 |
| Integration settings / export | 命令配置、生成预览、本地导出、指南 | 不向启动器配置目录偷偷写文件 |
| 快捷搜索 adapter | 单向 show/focus 现有面板 | 不模拟全局按键、不切换开关、不取得 Finder 选择 |

先扩展现有创建入口，不建一个通用插件框架。Core 保持 Foundation 与确定性规则；App Intents 定义放主 App target，避免另加扩展后出现第二份窗口或生命周期。

### 3.2 统一数据语义

请求至少包含：协议版本、可选请求 ID、可选文件名、可选精确模板 ID、正文来源、目标位置、接收方式。正文来源用枚举表达 `templateDefault` / `verbatimText`；空文本是 `verbatimText("")`，不能与未提供混为一谈。位置用枚举表达默认位置 / 外部目录建议 / 收藏目录 ID / 在面板选择。

来源由 adapter 决定：原生动作或外部链接。URL 不接受可改变信任的 `trusted`、`source` 或 `origin` 字段。普通外部链接显示“外部创建请求”，不凭链接声明画成可信启动器徽标。

## 4. macOS 快捷指令设计

### 4.1 动作一：在 FileMint 中打开文件草稿

名称采用“打开草稿”，避免“创建文件”让后续工作流误判已经产生文件。动作提供中英名称、描述和参数摘要；快捷指令可按 FileMint 搜到。

| 参数 | 默认 / 类型 | 规则 |
| --- | --- | --- |
| 模板 | 不指定 / `TemplateEntity?` | 精确 ID；选择列表只含现有启用模板，Finder 隐藏不影响启用状态 |
| 文件名 | 自动 / 文本 | 留空使用既有模板默认名称；输入完整名称时按第 6 节验证 |
| 保存位置 | FileMint 默认位置 / 枚举 | 默认位置、指定文件夹、常用文件夹、在 FileMint 中选择 |
| 文件夹 | 条件参数 / `IntentFile?` | 只在“指定文件夹”使用；验证目录类型，不读目录内容 |
| 常用文件夹 | 条件参数 / `FavoriteFolderEntity?` | 只列目录收藏；取稳定 ID，不把显示名称当 ID |
| 内容 | 模板内容 / 枚举 | 模板内容、指定文本、空内容 |
| 文本 | 条件参数 / 文本 | 指定文本时原样传入；可接上游文本变量 |

默认摘要只展示模板、名称和位置。内容及条件参数在编辑动作时按选择展开。实体查询基于 FileMint 已有配置快照，不索引用户文件或正文，不以逐次查询解析所有收藏书签。

原生条件参数按当前选择的模式映射：Shortcuts 会保留隐藏字段旧值，适配器只读取当前位置/内容枚举对应的字段，再校验必需值并生成互斥 typed request。隐藏的文件夹、收藏或文本不能覆盖当前模式或产生授权；公共 URL 的冲突字段仍拒绝整条请求。参数摘要与可选空值需验证实际 SDK 元数据及原生行为；“空内容”明确表达空字符串，不依赖系统是否把空参数变成 nil。此规则依据 2026-10-30 真实切换模式复现，取代设计期将隐藏值一并拒绝的假设。

### 4.2 动作二：显示 FileMint 快捷搜索

不带名称、正文、查询或分类参数。复用当前搜索的查询恢复、分类、焦点、IME 和模态保护；已经显示则聚焦，隐藏则恢复，绝不执行热键的 toggle 关闭行为。用户继续在 FileMint 内选择动作。

第一版不接收外部搜索文字，避免覆盖未完成查询。以后若需要再定义独立的查询交接契约。

搜索动作使用独立的展示结果，不套用草稿会话的成功条件：

| 结果 | 判定条件 | 对调用方的反馈 |
| --- | --- | --- |
| `shown` | 本次打开或恢复了搜索面板，面板已可见且搜索输入可接收键盘操作 | 成功：“快捷搜索已显示” |
| `alreadyVisible` | 搜索面板原本已显示，本次已成功聚焦其搜索输入 | 成功：“已聚焦快捷搜索” |
| `busy` | 原生模态、附属 sheet、退出/更新提交或现有独占操作阻止展示 | 失败：“FileMint 正在完成当前操作，请稍后重试” |
| `unavailable` | 配置/启动失败、展示超时或当前环境无法提供可交互面板 | 失败：“当前无法显示快捷搜索” |

现有 `QuickSearchPanelController.show()` 遇到模态时只聚焦模态并返回；方法返回、系统接受唤起或声明前台运行模式都不是搜索成功证据。实现时让展示入口报告上述结果，并核对当前窗口与会话，不能将未显示搜索的返回映射成成功。原生动作只有前两种结果正常完成，其余返回可读错误；URL 入口使用相同判定，但不承诺向启动器同步回传结果。模态优先、不排队，取消或超时后不得延迟弹出搜索；已有搜索内容仍按原契约保留。

### 4.3 草稿动作的执行及返回

- 主 App 内执行，等待配置就绪后原子接收；成功条件是草稿会话已建立且展示已交给当前窗口协调器。
- 成功返回“草稿已打开，等待在 FileMint 中创建”；不返回虚构文件 URL，也不等待用户完成草稿。
- 当前同 ID 草稿已呈现可返回 `alreadyPresented`；另一草稿、模态或写入占用返回可读错误，工作流不误报成功。
- 参数错误、实体失效、App 启动失败或无法进入前台必须明确失败；被取消的请求不能稍后突然弹出草稿。
- 后续快捷指令动作不能拿到“最终创建文件”。需要创建回执或后台自动化时，另设计可取消事务接口，而不是长时间挂起本动作。
- 锁屏、无人值守或不具备图形交互条件时不写文件、不循环要求前台；返回当前环境不能展示草稿。

### 4.4 应用与功能的最低系统版本

应用整体最低 macOS 13.0 保持不变；主 App、Finder extension、CorePackage、产品 QA 和安装/更新元数据使用 13.0。快捷指令与启动器接入单独要求 macOS 13.3，使用现有 ForegroundContinuable 路线，不增加旧系统回退。此规则覆盖设计期“候选通过后统一提高全 App 最低版本”的误解。

macOS 13.0–13.2 上保留接入页可见，明确说明需要 13.3，配置/预览/导出入口置灰；原生 Intent 注册按 API availability 保护。直接调用公开 draft/search URL 或其他接入入口同样在接收工作、预留操作和访问目录前拒绝；其他原有创建、Finder 和快捷搜索功能保持可用，不新增持久化开关。

应用包、appcast 与 Homebrew 保持最低 13.0，不因可选功能阻止安装或更新。功能版本判断、较新系统编译及模拟测试不能替代 macOS 13.0/13.3 实机运行；缺少环境时如实单列。既有证据及已发布安装包保持原样。

Apple 对[前台/后台执行](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)的说明也要求根据运行位置处理 UI。这里选择主 App 内的前台草稿动作；不新增只适合后台运行的 App Intents extension。

`IntentFile.fileURL` 可能为空；外部 URL 的读取需要相应 security-scoped 生命周期，见 [Apple 的 fileURL 说明](https://developer.apple.com/documentation/appintents/intentfile/fileurl)。不把 `IntentFile.data` 当目录，也不为了获得路径而读取目录数据。能否把系统给出的目录临时访问安全地移交给已返回的草稿会话，必须通过 P0 证明；无法保持时只保留目录建议，在点击创建时走原生授权，不能承诺零授权。

## 5. 公开 URL 协议

### 5.1 两个公开动作

```text
filemint://draft?v=1
filemint://search?v=1
```

`draft` 打开新草稿；`search` 仅显示/聚焦现有快捷搜索，参数只允许 `v=1`。host 是动作，path 必须为空；不同时支持多种等价路径拼法。

旧 `filemint://new?directory=...&template=...` 继续由旧解析器处理，不放宽字段白名单。不把旧链接自动升级成新能力；私有票据和文件工具路由保持自己的校验及信任边界。

### 5.2 草稿字段

| 字段 | 必须 | 语义 |
| --- | --- | --- |
| `v` | 是 | 字面值 `1`，未知版本拒绝 |
| `name` | 否 | 拟议文件名；缺省自动，空串或非法名称拒绝 |
| `template` | 否 | 现有启用模板的精确稳定 ID |
| `text` | 否 | 缺省用模板内容；存在时原样 UTF-8，`text=` 明确为空内容 |
| `directory` | 否 | 绝对本地目录路径建议，不是 `file://` 嵌套 URL |
| `favorite` | 否 | 当前设备的目录收藏 ID，不是名称或路径 |
| `location` | 否 | 唯一合法值 `ask`，在 FileMint 面板选择位置 |
| `id` | 否 | UUID 请求 ID，只用于进程内去重，不是票据或权限 |

`directory`、`favorite`、`location` 最多出现一个；都不出现时使用与 App 新建相同的初始目录。显式指定的位置失效，绝不回退到默认目录。未知字段也拒绝，避免调用方误拼 `directory` 后悄悄写到别处。

### 5.3 编码与解析

1. 对入口实际取得、尚未做字段解码的 URL 字符串先检查长度、scheme、host、空 path、无 fragment、无 user/password/port，再解析字段；不得先经会修复输入的 URL 构造器再声称完成原文校验。
2. 字段名大小写敏感，`v` 必须恰好一次。拒绝重复键、未知键、缺少值的键、畸形 `%` 和无效 UTF-8。
3. 每个值只百分号解码一次；`+` 按字面加号处理，空格写 `%20`。`%252F` 解码后仍是字面 `%2F`，不能再次解释为斜线。
4. 先编码每个参数值再组装 URL；不能编码完整 URL，不能把名字或正文拼进 shell 源码。
5. 拒绝 NUL；名称、路径和 ID 拒绝控制字符。正文可保留换行、制表符和原有 Unicode，但拒绝 NUL。
6. 目录必须是非空绝对本地路径；不展开 `~`、环境变量，不接受网络 URL，不解释脚本或模板变量。云盘挂载的本地路径仍按其实际可访问性处理。
7. `.` / `..` 目录组件做词法规范化，实际写入前仍要做路径解析和目标身份复核；词法清理不等于完成安全校验。

明确区分调用端原文、App 入口实际收到的 URL 表示和一次解码后的字段。当前 `AppDelegate.application(_:open:)` 收到 `[URL]`，其 `absoluteString` 不能未经验证就当作调用端原文；调用工具或系统在交付前是否规范化、拒绝或修复了输入，由第 13 节 P0 实测确认。

Core 字符串解析器对实际输入严格执行上述规则，单测可以证明其拒绝原始畸形字符串，但不能单独证明真实系统入口也保留并拒绝同一原文。若 P0 证明可通过受支持的入口取得原始事件字符串，则在构造 URL 前限额与校验，并避免与既有 URL 回调重复接收；否则公开保证限定为“校验 App 实际收到的 URL 表示”，明确上游已规范化的拼写无法追溯，不能承诺拒绝所有调用端畸形原文。不得尝试反向还原或再次解码来猜测原文。

两种结果都必须保留字段白名单、单次解码、解码后限额、路径/模板校验及单草稿确认。上游规范化不提供信任或授权，也不允许回退到私有快速创建。Foundation 的 URL 修复行为不能代替这些协议校验；P0 结论须同步到公开协议文案及真实入口回归用例。

### 5.4 有界输入

以下是 FileMint 拟议的产品限额，不是 macOS 或启动器保证的传输极限。以先触达的限制为准，不截断后继续。

| 输入 | 上限 |
| --- | --- |
| App 实际收到的编码后完整 URL（导出器也检查自己生成的表示） | 16 KiB |
| URL `text` 解码后的 UTF-8 | 8 KiB，同时受完整 URL 限额约束 |
| 原生 App Intent 指定文本 | 1 MiB UTF-8 |
| 名称 / 目录路径 | 1 KiB / 4 KiB UTF-8；最终名称另受文件系统实际规则约束 |
| 模板 ID / 收藏 ID | 各 256 UTF-8 字节，并校验实际 ID |
| 活跃草稿 / 启动期间待接收请求 | 各最多 1 个；无持续工作队列 |
| 请求 ID 去重记录 | 最近 10 分钟，最多 512 条，仅进程内元数据 |

过长正文提示“文本超过此入口的大小限制，请缩短，或通过快捷指令传入”。不得暗中走临时文件、正文路径、剪贴板或 localhost。导出器在生成时检查；接收端仍独立检查。

### 5.5 协议示例

以下示例只有实现后才可执行；不是本轮已上线能力。

```text
# 空白草稿，目录使用 App 默认位置
filemint://draft?v=1

# 精确 Markdown 模板与完整名称
filemint://draft?v=1&template=markdown&name=Meeting%20Notes.md

# 指定文本，换行与井号均被编码
filemint://draft?v=1&template=markdown&name=Notes.md&text=%23%20Notes%0A%0A

# 明确空内容
filemint://draft?v=1&name=Empty.txt&text=

# 在 FileMint 内选择位置
filemint://draft?v=1&location=ask&name=Notes.md

# 显式目录建议；example 是示例用户名，不自动创建该目录
filemint://draft?v=1&directory=%2FUsers%2Fexample%2FDocuments&name=Notes.md

# 恢复快捷搜索
filemint://search?v=1
```

`favorite` 示例由本机生成器产生真实 ID，避免复制一个看似可用的假 ID。它与自定义模板 ID 一样不保证跨设备可移植；分享时先提示收件人重新选择本地模板/目录。

`autoCreate=1`、`replace=true`、`command=...`、`callback=...` 或把私有票据字段混进公开草稿，全部视为非法请求，不局部执行。

## 6. 名称、模板与正文的完整关系

### 6.1 决策顺序

先验证模板是否存在且启用，再解析明确名称与后缀的关系，最后应用正文来源；冻结一个接收时间供整个草稿使用。不能先填正文又因选模板把正文覆盖掉。

| 输入组合 | 应有行为 |
| --- | --- |
| 无名称、无模板、无正文 | 沿用当前普通新建默认值 |
| 有模板，无名称 | 使用该模板的默认文件名和内容 |
| 名称不含后缀 + 明确模板 | 追加该模板后缀 |
| 完整名称后缀与明确模板一致 | 保留精确模板，不退回同后缀的另一个模板 |
| 完整名称后缀与明确模板冲突 | 拒绝请求，说明名称与模板不一致；不偷偷改名或换模板 |
| 只传完整名称 | 依现有名称规则决定格式，未知后缀仍只是文本后缀 |
| `text` 缺省 | 用所选模板原有内容与单次变量渲染 |
| `text` 存在，包括空串 | 标为用户已编辑内容，逐字保存，不展开 `{{year}}` 等占位符 |
| 文本模板 + 指定文本 | 保留模板身份与后缀，正文取明确文本；模板预设正文不再覆盖它 |
| Office 文档模板 + 指定文本，包括空串 | 拒绝；不把字符串写成伪 docx/xlsx，不向二进制注入文本 |
| Office 模板无指定文本 | 沿用已校验资产的精确字节复制、固定后缀和面板提示 |
| 模板停用、删除或资产损坏 | 明确失败或在草稿内阻止创建，保留输入；不换一个“相似模板” |

名称中的路径分隔符、逃逸和非法后缀复用 FilenamePolicy。字节限制是输入边界，不能拿它承诺所有卷都能保存任意名称。空白、隐藏文件名、组合后缀和 Unicode 的细节遵守现有命名契约；实现必须用现有生产规则和真实文件 fixture 验证，避免复制出第二套命名算法。

### 6.2 与现有行为相容

- 仍只有“创建”写文件；打开、预览、取消、目录选择取消不写用户文件。
- 创建前锁定输入与提交快照，沿用 exclusive create、增量命名及现有原子替换规则。
- 外部接口不接受覆盖策略。若面板遇到重名，由用户在原有流程处理；替换仍必须明确确认，默认取消，目录永不替换。
- 创建后行为仍使用现有开关与模板策略，面板显示有效动作；请求不能指定可执行文件、应用路径或 `openAfterCreate` 绕过开关。
- 正文不被当作 URL、脚本或第二轮模板解释。普通文本若恰好是 shell 内容，也只写文件，绝不执行。

## 7. 单草稿、重复请求和生命周期

### 7.1 原子接收表

| 当前状态 | 新草稿请求 | 对用户的反馈 |
| --- | --- | --- |
| 配置初始化中 | 只保留 1 个经限额的请求，等待就绪；初拟 5 秒启动预算，P0 实测后校准；超时拒绝 | 启动失败可重试，不延迟幽灵弹窗 |
| 空闲 | 接收并建立唯一会话 | 草稿可编辑，焦点落在名称 |
| 同 ID 同参数，原草稿仍在 | 不重复应用字段，聚焦同一草稿 | 已打开此草稿 |
| 另一草稿已在，无论是否编辑 | 不接收；聚焦原草稿，原文和 undo 保留 | “已有未完成草稿。新请求未打开。” |
| 准备图片/其他草稿中 | 拒绝，不抢占准备工作 | 完成当前操作后重试 |
| 正在创建文件 | 拒绝，不重复提交、不排队 | 正在创建，请稍后重试 |
| 存在原生模态、授权或替换确认（包括命令生成器 sheet） | 外部请求一律按当前模态优先；不叠第二个 sheet | 原生动作返回 busy；URL 不打断当前确认 |
| 退出/更新提交或其他独占操作中 | 按现有 coordinator 拒绝或先完成清理 | 当前操作完成后重试 |

生成器内用户主动点击“预览草稿”使用第 9.2 节的受控交接：先结束自己拥有的 sheet 展示，再进入同一接收链；这不是对模态检查的通用豁免。交接期间占用准备状态，外部请求不能插入；URL 和 App Intent 均不能声明自己拥有此交接权限。

“继续编辑”是旧草稿冲突提示的默认动作，“关闭提示”只移除提示。第一版不提供“替换旧草稿”按钮，避免一个外来请求获得丢弃用户输入的入口。需要新草稿时，用户完成或取消当前草稿，再从原工具重试。

URL 请求没有可靠的同步返回通道。旧草稿中的提示负责解释此次未接收；若用户停留在其他模态，不为拒绝消息再抢焦点或破坏当前输入。原生动作可直接返回 busy 错误。

### 7.2 去重与防重放

- `id` 相同且规范化参数摘要相同：活跃时复用原会话；会话已结束时返回 `alreadyHandled`，10 分钟内不重开。
- `id` 相同而参数不同：返回 `conflictingRequestID`，不改旧草稿。
- 只在内存保存 ID、参数摘要、状态和单调时间；不落盘正文、路径或其摘要，不输出日志。超出容量淘汰最旧记录。
- 没有 ID：按当前草稿占用规则处理；面板关闭后再次打开属于新草稿，仍须用户点击创建。
- App 重启后不承诺去重持久化；安全仍依赖草稿确认与现有原子写入，不依赖 UUID。
- 重复错误/重复调用合并展示，不形成弹窗风暴；忙碌期间不得每次调用都激活窗口。输入限额先于昂贵验证。

### 7.3 会话及访问归属

每次成功接收生成独立 session generation。目录授权、模板读取、应用图标和异步错误只可更新其所属会话；关闭后或建立新会话后，旧回调不得重新打开窗口、覆盖输入或抢焦点。

临时 security scope 由会话拥有，并在取消、失败或创建清理结束后释放；写入仍在进行时不能提前释放。若系统传入的 scope 在 Intent 返回后无法继续使用，就退回“待授权目录建议”，不要无限等待 Intent 或假装已有访问。

外部启动保持 accessory 行为：只显示草稿/搜索，不自动开设置或 Dock 图标。App Intent 的系统唤起与普通 LaunchServices 重开可能经过不同回调；P0 必须覆盖 `applicationDidFinishLaunching`、reopen 与 Intent 先后顺序，必要时增加最小启动展示协调，不能只依靠默认启动布尔值猜测。

P0 已观察到系统 reopen 晚于 Intent 返回，窗口归属因此绑定到外部草稿/搜索会话，而不是 perform 的调用栈。存在外部面板时，reopen 优先聚焦当前原生模态或最近的外部面板，保留输入，不自动开设置；用户仍可通过明确的设置菜单/按钮打开设置。外部面板关闭后清除其归属，无外部会话的普通启动/reopen 恢复既有设置行为。该规则只扩展本次新增外部会话，不改旧手动草稿入口；不得以进程名赋予请求信任，也不留下会吞掉将来启动的无限期一次性标记。

### 7.4 响应性与可诊断性

以主 App 实际收到请求为计时起点，热启动目标为 p95 在 300 ms 内给出草稿或明确接收状态；冷启动目标为 p95 在 2 s 内可操作。两者是待 P0 校准的工程目标，不把系统启动器启动和调度耗时混入 App 内延迟，也不当作当前性能证据。

解析与廉价字段校验先行；书签、模板资产及文件访问离开 UI 线程，完成后核对会话 generation。大收藏目录只查询已有快照，输入筛选不触发逐项 I/O。没有可量化进度时使用短状态文字，不展示虚构百分比。

自动测试注入时钟和依赖，生产只保留有界、无用户数据的本机诊断事件。支持场景需要导出诊断时由用户显式操作，默认不附路径、文件名、正文或完整 URL；不增加埋点或远程分析。

## 8. 保存位置与权限

1. 未显式指定位置：复用 App 的首个配置目录或系统解析的用户主目录，并在面板中可见；不使用上一轮 Finder 位置。
2. 指定路径：作为本次目录建议。打开草稿不为此扫描目录、登记 Finder 监控或保存新 bookmark。
3. 指定收藏：只接受目录项，执行时解析 bookmark 并校验身份和类型。收藏拥有可定位访问不代表拥有创建写权限。
4. 指定“在 FileMint 中选择”：先打开面板，位置显示“选择保存位置…”，用户从现有 Save Location 操作选择；不在草稿之前弹一个孤立选择器。
5. 点击创建时，复用当前有效写访问；没有访问时，通过原生选择器授权准确目录。TCC 拒绝时保留草稿，提供重试/选择其他位置；不要求新开辅助功能、输入监控或自动化权限。
6. 如选择器最终选择了另一个目录，先更新草稿位置并回到面板，用户再次创建；不能在不易察觉的位置替用户保存。
7. 目录不存在、变成文件、卷离线、只读、收藏身份变化时，保留名称和正文，解释原因并提供重新选择；不创建目录树，不改用父目录或默认目录。
8. 创建前复核实际目标及访问，处理 symlink/路径替换，不能把路径字符串相同当作目录身份相同。
9. 手动草稿选择目录沿用手动创建授权边界；Finder 菜单及私有快速请求仍受 Finder scope 限制。外部参数不能修改这些配置，也不能把文件工具引向范围外位置。
10. 此次临时授权不自动变成永久配置。想长期加入 Finder & Folders，用户走原有明确的设置操作。

### 9.1 信息架构

页面从上到下：

1. 标题“快捷指令与启动器”，说明“配置好模板和位置，日常只填名称，确认后创建”。
2. “从一个常用场景开始”：用简洁原生行提供第 2.1 节的项目笔记、工作流文本和快捷搜索，每行展示用途和一个开始动作。
3. 两行工具入口：快捷指令、Raycast。选择场景和工具后，进入对应短指南或带入该场景的同一生成器，保留工具各自真实的安装步骤；本期不展示 Alfred 入口、禁用按钮或“即将推出”占位。
4. “自定义命令…”次级入口：展开全部配置；快捷搜索链接也可在其场景内复制。不把 URL 编辑、脚本内容或协议字段放进首次接入主路径。
5. 按需帮助：大小限制、链接包含数据、真实测试状态与常见问题；不默认展开一整页排障说明。

| 入口行 | 主动作 | 次动作 | 不应出现的误导 |
| --- | --- | --- | --- |
| 快捷指令 | 设置示例动作… | 打开快捷指令 / 自定义参数说明 | 不承诺系统支持直接跳到 FileMint 动作筛选或自动填好参数 |
| Raycast | 创建启动命令… | 导入步骤 / 实际测试 | 未导入不能显示“已连接” |

无总开关、账户登录、API Key 或服务运行状态。动作是显式发起的草稿入口；原生动作的可发现性也不能靠一个自定义开关可靠撤回。第一版不引入一套虚假的授权管理。

“打开快捷指令”通过系统打开应用；如无法可靠深链到动作目录，旁边保留“搜索 FileMint，添加‘打开文件草稿’”说明。没有独立确认过的系统私有深链不进入产品。

首次接入按“选择场景与工具 → 配置模板和位置 → 添加动作或导入命令 → 从真实工具运行 → 核对草稿并创建”引导。工具安装和支持版本等前置条件在开始前说明；用户无需阅读协议、打开终端、手改脚本、复制模板 ID 或拼接 URL。快捷指令使用同屏短步骤和合成文本示例指导用户在系统 App 中配置原生参数；Raycast 使用导出后对应的导入步骤。步骤返回保留当前生成器会话，禁止为展示“完成”而默认创建文件。

固定位置的引导先说明命令绑定与目录访问的区别：可复用既有配置中仍有效的写访问；需要新增长期使用目录时，在创建命令前引导用户通过既有 Finder & Folders 操作明确配置，并说明这会保存目录授权及调整对应 Finder 范围。用户也可保留临时位置，但应知道它可能再次需要授权；不得用导出或首次测试替代长期授权同意。原生快捷指令设置步骤及导出后的导入/实测指南均展示在非模态设置内容中，确保用户从外部工具运行时不会被接入 UI 自身阻断。

收到测试请求、草稿已显示、文件已创建分别按实际事件反馈。接收状态仍遵守第 10.3 节的会话内证据，不新增虚假的“已连接”标记或后台探测服务；临时访问和配置失效的恢复入口与首次接入使用相同文案与授权边界。

### 9.2 命令生成器

使用附属于设置窗口的原生 sheet，标题“创建启动命令”，不另开管理窗口。建议起始 680 × 650 pt，内容可滚动、底部动作固定，尺寸随可用屏幕夹紧。

从入门场景进入时先展示模板、保存位置和简短的运行摘要，例如“在 Raycast 输入笔记名称，确认后保存到所选目录”。命令名称给出可编辑默认值，工具沿用用户刚才的选择，文件名默认“运行时填写”；不要求用户重复做已经明确的选择。指定正文、固定名称、通用链接等选项收在“自定义”内；场景与完整配置共用同一状态、校验、预览和导出路径。

基础区按使用顺序排列：

- **命令名称**：如“新建项目笔记”，只命名导出物，不写入全局偏好。
- **文件模板**：可搜索现有启用模板；显示名称与后缀，内部用 ID。
- **保存位置**：默认位置 / 常用目录 / 选择目录 / 每次在 FileMint 选择。完整位置可通过可选择文本查看；收藏失效即阻止生成该绑定。
- **文件名**：固定名称，或 Raycast 的“运行时填写”；运行时名称由 Raycast 参数承载。通用链接使用固定名称或省略名称沿用默认值，不提供无接收方的运行时输入选项。
- **初始内容**：默认折叠；模板内容 / 指定文本 / 空内容。切换模板不抹除用户已输入文本。
- **使用方式**：通用链接 / Raycast。快捷指令使用原生参数，另有动作指南，不把长文本绕回链接。

展开“查看链接”才显示只读、可选中的编码 URL。普通用户只见清楚的模板和位置；ID、编码与 shell 都不占据正常路径。

底部一个主动作随方式变化：“复制链接” / “导出 Raycast 脚本…”。次动作“预览草稿”，以及“取消”。预览走同一 typed request 接收链；只打开草稿、不写文件，已有草稿时同样提示未接收。

导出成功后，结束生成器 sheet 展示并转到设置页的非模态导入/实测指南；复制链接后进入实测指南也使用同一交接。会话配置只为“返回编辑”保留，等待用户导入或外部调用期间不占用 admission，不自动恢复 sheet。用户明确返回编辑且没有其他模态时才恢复原生成器；外部请求仍执行全部原有校验。导出失败或取消只留在生成器内，不显示测试就绪。设置关闭、会话取消或被新配置取代时释放暂存状态，不在后台重开窗口。

预览的窗口交接顺序固定如下：

1. 先验证输入，并由主 App 协调器原子检查草稿/准备/写入及其他模态状态。已有草稿或其他占用时，保留当前生成器并在其中提示未接收，不关闭旧草稿、不把焦点移到 sheet 后面。
2. 可交接时短暂占用准备状态，保存生成器的会话、输入、选择和焦点；结束其 sheet 展示并等待完成，再按同一接收链复核状态、建立草稿。只允许当前生成器拥有的 sheet 执行此内部动作，授权、替换确认及其他窗口的 sheet 不能被关闭或跳过。交接失败释放占用，并在所属设置窗口仍有效时恢复生成器和错误说明。
3. 预览草稿取消或成功创建并结束会话后，恢复同一生成器配置，焦点回到“预览草稿”。写入失败或授权取消仍保留草稿时不恢复生成器；草稿中的修改不反向覆盖命令配置。
4. 交接和恢复均核对生成器会话、所属设置窗口及本次预览草稿的归属，旧回调不能触发另一会话。设置已关闭或会话已取消时释放配置，不继续尚未完成的预览交接、不重新打开窗口；已建立的草稿保留原有独立生命周期。用户切到其他 App，或另一个模态仍在时，延后到用户主动回到所属设置窗口且模态结束后恢复，不抢焦点。交接只是暂停展示，不视为用户取消生成器，也不重新生成配置。

文件名和正文按原样显示，无 HTML 渲染；开始输入时不立即标红，离开字段或提交后显示可纠正错误。针对 URL 超限、无模板和目标冲突显示字段级提示，不能把所有错误都交给一个“失败”弹窗。

有文本时，在链接/导出动作附近只显示一次“文本会包含在链接及导出文件中”。复制只在明确点击时写剪贴板，内容改变后清除旧“已复制”状态。导出成功显示实际保存结果；取消 NSSavePanel 无成功提示。

生成器未保存的配置仅存在当前会话；用户关闭/取消或所属设置窗口关闭时释放，预览交接或导出后非模态指南期间按上述规则保留。导出包含路径、正文及本机 ID，分享前提示其可移植性和数据内容；不自动上传、登记云端模板或发布启动器商店。

### 9.3 接收后的创建面板

保留现有原生创建面板，避免让用户学习第二套表单。面板顶部加一条低强调的来源说明：快捷指令或外部创建请求；主标题仍是“新建文件”。

名称优先、格式/模板明确、位置始终可见，正文沿用现有编辑器。正文较长时局部滚动，不撑高整个面板；“创建”固定可见。名称已完整时初始选中主名称而尽量保留后缀，保留既有命名语义和 undo。

首屏必须回答“准备创建什么、存在哪里、带入了什么、下一步做什么”，以第 14.3 节的第一眼测试验收：

- 文件名及后缀是最强的信息层级，精确模板名紧邻格式；目标目录持续可见，长路径保留足以区分同名目录的上下文，并可一次展开完整、可选择的文本。
- 文本草稿直接显示真实正文开头及编辑入口；空内容明确呈现空白状态，不插入占位文字。Office 草稿展示文档类型和沿用模板原文的说明，不伪装成可编辑文本预览。
- 用户进入的是待确认草稿，不能出现让人误以为已保存的成功标记。“创建”或有效的“创建并打开”始终可见；创建后定位/打开行为按现有开关与模板策略明确呈现，不自动开启。
- 名称、模板、正文和位置已经完整时，不再弹额外确认、不要求重新选择；直接点击创建或使用既有 Command-Return 即可提交。授权、重名替换及错误处理仍按现有规则出现，且保留输入。
- 未遇到问题时保持简洁，不把来源说明、接入帮助和技术状态堆成警告区域；需要行动时在对应字段附近给出原因和恢复动作，不让全局失败弹窗取代可操作提示。

接收说明不是警告横幅；只有未接收、无访问、目标不可用等需要行动的情况才使用提示。路径过长中间省略时，仍提供完整可选文本与 VoiceOver 内容。

交互原型用于观察信息层级、生成器、已有草稿与授权状态；它不替代原生 SwiftUI/AppKit 的焦点、色彩及系统授权验收。

### 9.5 键盘行为

- 创建面板继续沿用 Return 在单行创建、正文 Return 换行、Command-Return 创建、Escape 取消、Tab/Shift-Tab 逐项循环的契约。
- 生成器中 Return 按当前字段原生语义工作；Command-Return 执行已标明的生成/导出主动作，绝不隐式创建文件。
- IME composition、展开菜单与原生选择器先消费 Return/Escape；一次按键不能同时完成输入法和提交操作。
- 首次打开 sheet 焦点到首个字段；取消返回原触发按钮。预览草稿结束后按第 9.2 节恢复原生成器会话与“预览草稿”按钮焦点，不重建或丢失配置，也不在后台强行恢复窗口。
- 快捷指令/URL 的 show-search 是单向显示，只有原有全局热键保留再次按下收起的语义。

## 10. 本期接入与二期保留设计

### 10.1 Raycast 首个版本

导出原生 Script Command，提供“打开文件草稿”与“显示快捷搜索”两类命令。入门项目笔记命令固定模板和位置，运行时只有名称一个输入；短文本作为高级配置才可另加，最多使用两个输入，避免把多行正文和复杂参数挤进启动器搜索框。

[Raycast 官方参数文档](https://github.com/raycast/script-commands/blob/master/documentation/ARGUMENTS.md)提供 `percentEncoded`，并限制 Script Command 参数数为 3。导出器对运行时值使用此能力，对固定值预先编码一次，不能双重编码。

脚本只调用系统 `/usr/bin/open`，使用固定 bundle identifier 定向 FileMint，参数保持独立并正确引用。固定配置只能以验证后的编码数据写入脚本；不得把用户的 `$()`、反引号、引号或多行文本写成可执行 shell 表达式。无 `eval`、无命令字符串再执行、无 Python/Node/Swift 运行时依赖。

导出器预留协议长度余量，但接收端仍拒绝超限；没有足够信息证明 Raycast 成功接收时只显示“脚本已导出”。安装指引为：保存到用户选择的脚本目录 → 在 Raycast 添加该目录 → 查找命令 → 实际执行。

不得从 `open` 的退出 0 推断“草稿打开成功”或“已创建文件”。失败可输出无数据的诊断文字与安装提示，不回显完整 URL。

### 10.2 Alfred 二期保留设计

用户最新决定将以下 Alfred 工作流导出、安装说明、真实入口验收和宣传整体移至二期。本期不实现或展示 Alfred 专用设置，也不以编码器探针或通用 URL 能力宣称 Alfred 联动可用；以下仅保留设计，启动二期时再核对环境和契约。

导出标准 `.alfredworkflow`，包含可配置关键字（默认 `fm`）、名称输入、固定模板/位置配置，以及显示快捷搜索的独立命令。说明需要支持 Workflow 的 Alfred Powerpack；不把付费能力描述成免费版已可用。

工作流使用 [Run Script 的 argv 输入](https://www.alfredapp.com/help/workflows/actions/run-script/)传递名称，绝不把 `{query}` 插进 shell 源码。固定、随工作流附带的 JXA 编码器接收 argv，用标准百分号编码产生 URL，再由 shell 中固定的 `/usr/bin/open -b` 以一个参数交付；不向 Finder 或其他 App 发送 AppleScript 自动化命令。二期开始时需通过其独立边界验证证明此系统解释器方案不引入额外权限或环境依赖，并用真实 Alfred/Powerpack 验收导入和调用。

不依赖 Open URL 对象的隐含编码，避免空格、`&`、`#`、`+` 或 `%` 被错误解释。工作流导入由 Alfred 自己确认；FileMint 只导出，不改用户 Alfred 数据目录、不覆盖既有同名 workflow。更新包保留稳定 workflow ID，让 Alfred 展示自身更新/导入交互。

### 10.3 安装及真实状态

只展示有证据的状态：“尚未导出”“已保存到所选位置”“已在 FileMint 收到测试请求”。本机预览只证明本机路由，不证明启动器导入完成；本页按钮成功打开第三方 App 也不证明工作流可用。

“测试”用不含私人正文的测试草稿，明确仍须取消或创建；只有收到本次实际请求并匹配进程内测试 nonce，才更新“FileMint 已收到”。它不冒充持久连接、签名认证或用户创建成功。

自定义 URL scheme 可能被其他 App 注册，见 [Apple 的说明](https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app)。官方脚本/工作流尽量按 bundle ID 定向调用；裸链接不承诺目标 App 唯一。首版不为此引入公网域名和 Universal Links。

首次测试成功后，指南直接说明下一次从哪里调用、只需输入什么，以及模板/位置变化时如何重新配置；不把用户带回协议说明。重复调用复用正常命令，不携带固定的测试请求 ID，以免被第 7.2 节去重规则拦住。接入与权限状态不靠“测试成功一次”永久推断。

## 11. 错误与恢复文案

| 错误码 / 状态 | 文案示例 | 恢复动作 |
| --- | --- | --- |
| `invalidRequest` | 无法打开此创建请求。请检查链接格式。 | 查看接入说明；不展示或复制完整正文 |
| `unsupportedVersion` | 当前 FileMint 不支持此链接版本。 | 检查链接或打开 About 检查更新，不自动更新 |
| `invalidFilename` | 文件名不能包含路径，请只填写名称。 | 返回原工具修改，或在生成器字段改正 |
| `templateUnavailable` | 所选模板已移除或停用，请重新选择。 | 显式选模板，不自动启用或替换 |
| `contentTemplateMismatch` | 此文档模板不能接收文本内容。 | 使用模板原文，或改为文本模板 |
| `payloadTooLarge` | 文本超过此入口的大小限制。 | 缩短；转用原生快捷指令，仍遵守其上限 |
| `existingDraft` | 已有未完成草稿。新请求未打开。 | 继续编辑；完成或取消后重试 |
| `busy` | FileMint 正在完成当前操作，请稍后重试。 | 原请求不排队，用户重试 |
| 搜索 `shown` / `alreadyVisible` | 快捷搜索已显示。 / 已聚焦快捷搜索。 | 用户继续选择动作；不报告草稿或文件已创建 |
| 搜索 `unavailable` | 当前无法显示快捷搜索。 | 返回可交互环境后重试；取消或超时后不晚弹窗 |
| `destinationUnavailable` | 保存位置目前不可用。 | 检查卷/权限或选择其他目录，保留名称和正文 |
| `authorizationRequired` | 需要允许访问此保存位置。 | 原生目录选择，取消保持草稿 |
| `authorizationDenied` | 未获得保存位置的访问权限，草稿已保留。 | 重试/选择其他位置 |
| `conflictingRequestID` | 此请求标识已用于其他内容，请重新发起。 | 调用端生成新 ID |
| `alreadyHandled` | 此请求已处理，请重新发起以打开新草稿。 | 不用旧 ID 重开 |
| write error | 未能保存文件，草稿已保留。 | 沿用现有具体错误与重试 |
| post-open error | 文件已保存，但未能打开。 | 展示真实回执，定位/重试打开，不能再创建一份 |

字段错误靠近字段；保存错误在草稿内；结构非法链接用有界、非连续弹出的请求错误反馈。系统模态优先、错误不抢另一个会话的焦点。日志只记录无数据错误码、入口种类、版本和耗时，不记录路径、名称、正文、完整 URL、bookmark 或用户内容摘要。

## 12. 安全和兼容边界

- 外部链接是不可信输入；所有公开字段白名单校验，私有票据不在公开协议中。
- 无 `autoCreate` / `replace` / 任意执行 / 远程内容读取 / 回调 URL；也没有据此申请辅助功能、输入监控、Automation 或 broad filesystem entitlement 的理由。
- 链接可能留在调用工具、用户剪贴板或 shell 调用信息中。FileMint 不记录它不代表其他工具不留存；正文较长或敏感时优先原生参数，不宣称原生工作流本身没有历史记录。
- 无正文临时文件桥接、URL 自动下载、预览远程图片、目录遍历或剪贴板监听。
- 旧公开路由、私有票据、Finder、菜单、Quick Search 和三个原有创建入口保留原行为；扩展 typed request 不允许削弱其认证和 scope。
- 设置无新增必需持久字段；导出配置先用会话内状态，避免自动保存敏感正文。未来若保存命令预设，必须另行决定保存范围和导出/删除语义。
- 原生动作标识、实体 ID 和 URL v1 发布后保持稳定。显示名称可本地化；不按本地化名称查询模板。
- 未知版本拒绝；增添字段前决定版本策略。首版严格解析，不能让新版本字段在旧 App 中静默降级。
- 应用最低系统保持 13.0，只有接入功能要求 13.3；旧系统禁用该功能，不维护回退实现，不把功能 API 门槛提高为产品最低版本。不承诺 Intel 或未测试系统/启动器版本的运行证据，发布兼容表必须绑定实际 arm64 / 系统 / 启动器版本。

### P0：URL 原文与系统交付边界

- 样本包括：裸 `%`、不完整/非法 percent、无效 UTF-8 percent 序列、裸空格/中文、合法 UTF-8 编码、`+`、`%25`、`%252F`、保留分隔符、重复/未知字段，以及完整 URL 和解码字段限额的边界值。对每条样本区分调用工具拒绝、工具编码、系统拒绝、系统交付和 FileMint 接收/拒绝，不把前几种算成 FileMint 拒绝成功。
- 对照调用端合成原文、交给系统的表示、App 回调实际收到的表示及解析结果；若某层不可观察，标明未知，不推断字节保真。探针只记录隔离测试数据，不能为生产新增完整 URL、路径或正文日志。
- 核实是否存在受支持且适用于当前主 App 生命周期的原始事件字符串入口；如可用，验证限额先于 URL 构造、冷/热启动接收及与既有回调的去重，不引入私有 API 或第二条快速创建路径。如不可用或无法证明保真，采用第 5.3 节的“实际收到的表示”保证，列出观察到的上游规范化差异，不猜测原文。
- P0 退出前将选择的接收入口、各层可观察性、真实输入输出及未覆盖环境记入证据；据此定稿第 5.3 节与第 14 节用例，再更新 owning SPEC。所有可交付到 App 的非法字段、越限和越权请求仍须拒绝；上游规范化后的合法表示只能进入待确认草稿，不能自动写入。

5 秒只是理解测试的观察窗口，不是从启动器到保存完成的耗时承诺；无需背出全文或完整长路径，但必须能辨认正确位置并找到完整路径入口。首次观察在解释草稿界面或练习取消/创建之前记录；后续样本覆盖有正文、空内容、Office 模板，以及长名称/同名末级目录、当前最小窗口、中英界面，作为边界理解检查，不混称为首次观察。仅给体验者看其理解的语言，无障碍和原生键盘另外按第 14.2 节验证。运行响应仍按第 7.4 节测量，不能用剪辑或截图掩盖等待。

每项附实际观察和失败后的修正记录；缺少首次使用者或本期工具环境标 `blocked`，不能把计划、原型或自动用例算作用户体验验收。修正后只重测受影响路径，但本期核心体验未通过时不得标记本功能完整交付。Alfred 不计入本期人数或通过条件；体验验收覆盖 P0 最终选定的支持范围，不维护按系统版本分叉的流程。

### 14.4 完成标准

1. 本期 Shortcuts、Raycast 两种目标工具通过真实入口带入正确参数，通用 URL 另完成真实系统交付验证；覆盖空白、文本模板、外部正文和显式位置。Alfred 导出、安装、实测与宣传不计入本期完成条件。
2. 外部调用和所有取消路径都不创建用户文件；只有点击创建后的正确回执算写入成功。
3. 已有草稿、畸形参数、无访问目录、失效模板、并发和重复请求都不会丢输入、静默写入或错目录保存。
4. 安装/导出指南可实际复现，明确权限、系统与启动器版本；不要求用户安装编程运行时。
5. 交互、明暗色、中英和无障碍覆盖通过；已知环境缺口和回退路径记录在任务。
6. 产品、文档与测试对“已接收”“已呈现”“已创建”的用词完全一致。
7. URL 原文可得性及上游规范化边界有 P0 证据，协议保证与实际可校验层一致；搜索成功对应可交互面板，生成器预览交接不豁免外部请求的模态保护。
