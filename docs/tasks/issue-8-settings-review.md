## 共同设计规则

- 保持“文件创建 / 扩展功能 / 偏好设置”三组侧栏及现有页面顺序。
- 初始窗口仍为 1040 × 720，最小 960 × 680；内容较长时滚动，控件不得因英文或大字号被遮挡。
- 详情页横向边距 30，分组间距约 24，行内容左右约 16；控件统一靠右。
- 原生小尺寸开关、菜单控件和清晰的文字标签；图标为辅助信息。
- “在 Finder 中显示”只说明 Finder 入口；“启用”用于确实控制整个模块的开关；新建操作与模板的“菜单位置”统一提供隐藏/一级菜单/二级菜单。其他模块的功能开关保持原有语义。
- 设置保存失败恢复到已提交状态并显示错误；导航、折叠和审核原型的场景切换不写产品设置。
- 中英文同步设计，深浅色、键盘和 VoiceOver 均保留。动画遵守减少动态效果设置。
- 本原型中的 Finder 菜单预览和权限场景切换属于审核工具，不要求作为产品常驻界面上线。

## T1：统一 Finder 菜单相关配置

### 具体设计

“创建行为、文件（夹）工具、资源工具、使用 App 打开、常用文件（夹）”的首个功能分组均为 **Finder 菜单**。
该分组位于页面说明下面，不藏在单独标签页或列表底部。标题与首行位置一致。

| 页面 | 首组内容 | 随后内容 |
| --- | --- | --- |
| 创建行为 | 三个独立操作行：名称＋说明、菜单位置下拉、图标配置；二级菜单根图标 | 文件重名处理、创建后行为 |
| 文件（夹）工具 | 现有模块开关、根图标、功能行的开关与位置 | 与对应功能相邻的移动/删除选项 |
| 资源工具 | 在 Finder 中显示总开关、根图标、可展开的七个子项 | 直接使用工具的七个入口与本地处理说明 |
| 使用 App 打开 | 根图标、按下方 App 列表显示的简短说明 | App 列表；各 App 保留自己的菜单位置和终端打开方式 |
| 常用文件（夹） | “显示添加入口”“显示常用列表”两个独立开关、根图标 | 搜索、收藏列表和邻近的添加/批量操作 |

资源工具取消“使用工具 / Finder 菜单设置”标签切换，两个区域同页可见。子项设置可折叠，但总开关和当前启用数量一直可见。
折叠不会禁用功能。资源工具 Finder 开关关闭时，App 内“选择图片”仍可用。
文件工具的总开关关闭后保留所有子项选择；子项区仍可见且不能编辑。资源工具也保留已有子项选择。

“使用 App 打开”继续没有模块总开关，不为了版式统一增加新控制。其 App 行仍然是菜单位置的唯一编辑处。
常用位置两个开关也不合并，避免用户只能同时显示或同时隐藏。

### 实现细节

- 在 App 层复用 Finder 配置分组、设置行和图标行，不把整个页面抽成高度参数化的通用组件。
- 共享行统一 label、description、控件尾对齐；不同模块保留自己的 Binding、禁用条件及保存逻辑。
- 仅调整布局，不改模块默认值、选择适用性、排序、菜单请求或授权范围。
- 涉及 `SettingsSections.swift`、`FileToolsSettingsView.swift`、`ResourceToolsView.swift`、`OpenWithSettingsView.swift`、`FavoriteLocationsView.swift`。
- 实施前更新 presentation，以及改变资源工具标签组织的 resource-tools 契约；其他模块的行为契约保持原意。

### 验收

- 五个页面都能在首个分组找到 Finder 配置；没有第二套重复开关。
- 资源工具关闭 Finder 集成后仍可从 App 启动；重新开启恢复子项。
- 使用 App 打开的空列表、单 App、多 App；常用位置空列表和长列表均保持配置可见。
- 中英文、深浅色和最小窗口下对齐一致；键盘可访问所有可用控件。
- 原型：审核入口“1 菜单设置”；切换上述页面，关闭模块并尝试其 App 内入口。

## T2：新建操作和每个模板独立配置菜单位置

### 统一的设置行

三个新建子功能统一采用 **名称＋说明｜菜单位置下拉｜图标配置**：

| 名称 | 说明 | 菜单位置选项 |
| --- | --- | --- |
| 新建文件… | 填写文件名、格式和内容后创建 | 隐藏 / 一级菜单 / 二级菜单 |
| 从剪贴板新建… | 读取一次剪贴板文字，确认后创建 | 隐藏 / 一级菜单 / 二级菜单 |
| 图片粘贴为文件… | 将剪贴板中的单张图片保存为 PNG | 隐藏 / 一级菜单 / 二级菜单 |

移除原来的整组“菜单位置”设置。三个动作可以混合放置，例如新建文件放一级、剪贴板文字隐藏、图片操作留在二级。
不再额外摆放一个重复的显示开关；位置下拉中的“隐藏”就是 Finder 入口的显隐控制。
新安装默认三个操作均在二级菜单；已有安装按原来的整组位置迁移，不能擅自把一级菜单用户改回二级。
二级“新建文件”根菜单保留自己的图标设置，说明“只在存在二级菜单内容时显示”。
三个子功能的图标始终分别保存，不因隐藏或换层级被清空。

### 每个模板的菜单位置

在“模板与类型”的每个模板行提供单独的菜单位置下拉，使用稳定模板 ID 保存。按实施反馈移除列表中的图标编辑按钮；保留当前图标展示与编辑面板内的图标设置。
内置文本、内置 Office、自定义文本和导入 Office 模板均适用；相同后缀的两个模板也可处于不同层级。
模板的名称/说明在左侧，菜单位置和编辑入口在右侧。三个新建子功能仍保留各自的图标配置。

**模板启用状态不能与 Finder 隐藏混为一谈。** 现有 `isEnabled` 还影响快速创建与类型选择器，继续保留其独立含义。
原型将模板启用开关放在名称前，位置下拉仅控制 Finder。模板未启用时，位置下拉置灰并保留原值；重新启用恢复该位置。
已启用模板选择“隐藏”后，保留模板本身及既有 App 内使用能力。位置调整不改变模板顺序、默认模板、内容、创建后动作或 Office 资产。

### 模板滚动与行交互

- 列表继续按需生成行；悬停状态保存在行内，普通滚动不触发整页悬停刷新或整列动画。
- 每份模板列表快照统一计算默认模板标记，避免每个可见行重复筛选、排序全表。
- 拖拽、上移/下移仍使用受减少动态效果控制的局部重排动画；保留稳定 ID、选择和滚动交互。
- 原生复查默认列表和长列表的滚动、滚动后选择/编辑、行内控件与拖拽，并区分观察结果和量化性能证据。

### 模板双击编辑与页面入口

- 移除模板页底部的“设置三个新建操作”跨页入口；创建行为仍通过侧栏进入。
- 双击任一模板的名称、说明或行内空白，打开该模板已有的编辑面板。已停用的模板仍可编辑。
- 单击继续选择模板，不直接进入编辑。保留可由键盘访问的“编辑”入口；原型以每行铅笔按钮表示。
- 双击启用开关、菜单位置下拉和其他行内控件，不触发行编辑；拖拽排序也不触发编辑。图标只在编辑面板内修改。
- 双击与现有编辑按钮调用同一编辑方法，以稳定模板 ID 定位；不创建副本、不新建文件、不改变当前启用状态或菜单位置。
- 编辑只生成草稿；明确保存后才更新。取消或 Escape 丢弃本次编辑，保留原模板；已有面板不重复打开。
- 文本模板沿用名称、扩展名、默认文件名、初始内容和既有创建后动作编辑；Office 模板沿用固定格式及原有内容限制，不把二进制内容当文本编辑。
- 模板编辑面板默认直接显示“菜单位置”下拉，提供“隐藏 / 一级菜单 / 二级菜单”；不放入高级选项，也不依赖其他功能开关。文本与 Office 模板均支持。
- 编辑面板与列表行操作同一份按模板 ID 保存的菜单位置，不另建一套设置。打开已有模板时回填当前值；新建默认二级，复制继承源模板位置。
- 面板中的菜单位置属于编辑草稿，与其他字段一起保存；取消或 Escape 不改变列表和 Finder 菜单，保存失败保留草稿。保存成功后列表与后续 Finder 菜单同步更新。
- 停用模板也可在编辑面板预先配置菜单位置，保存不会自动启用模板；启用后才按该位置显示。
- 沿用既有校验、保存失败保留草稿及偏好原子提交；不以双击入口替换或简化这些规则。

编辑面板菜单位置为任务补充，按用户要求仅记录在此；当前原型不追加该控件，也不为该补充执行原型验收。

### 数据、复制与迁移

- 三个固定操作分别保存类型化的 `hidden / main / submenu` 值。
- 模板位置建议存为偏好中的 ID → 位置映射；与模板内容、现有 `isEnabled` 和自定义图标独立。
- 从旧设置迁移：每个固定操作与每个现有模板继承旧 `newFileMenuPlacement`；模板 `isEnabled`、排序、图标及其他偏好保持原样。
- 缺失/非法的单项值独立回退到旧位置；旧位置也无效则回退二级。合法邻项不能一起丢失。现有损坏设置恢复规则不变。
- 新增模板默认二级菜单；旧版本升级追加的默认禁用模板继续禁用，不因位置默认值进入 Finder。
- 复制模板继承源模板的菜单位置和图标；保存启用模板、排序和默认引用处理仍遵循已有复制契约。
- Finder 菜单布局属于本机偏好，不加入 `.filemint-templates` v1 交换格式。导入跳过项保留本机位置；新导入/另存副本使用二级位置，保留导入流程确定的启用状态。
- 删除模板时清理对应本机位置映射；显式恢复内置模板时恢复内置位置默认值，自定义模板不受影响。
- 保存为一次原子偏好更新，失败恢复旧值；并发模板导入仍使用现有偏好提交边界。

### Finder 菜单生成

先按位置分组，再按原有相对顺序生成：

- 一级区：放在一级的固定操作，再接放在一级的已启用模板。
- 二级区：放在二级的固定操作，再接放在二级的已启用模板；根入口放在这一组一级创建项之后。
- 每个入口只出现一次，不能同时出现在两层。
- 同一层中，固定操作与模板都非空时才加分隔线；仅有模板不能有顶部空白分隔线。
- 没有任何二级内容时隐藏根菜单，一级项仍显示。
- 所有创建项均隐藏或模板未启用时，完全不显示新建菜单组；其他工具菜单正常。
- 隐藏 Finder 入口不会取消已有草稿/任务，不读取剪贴板、不扫描目录，也不充当系统权限开关。

### 实现与验收

- Core：偏好迁移、按稳定 ID 取位置、纯菜单分组规则。FinderSync：根据分组结果生成唯一菜单项。
- App：创建页、模板行和模板编辑面板复用菜单位置选项；面板绑定草稿，列表绑定已保存值，模板保留独立启用语义；图标编辑继续使用已有能力。
- 涉及 `Preferences.swift`、菜单布局规则、`FinderSync.swift`、`SettingsSections.swift`、`TypesPane.swift`、`PreferencesModel.swift`。
- 实施前更新 creation、templates、startup、presentation 契约。
- 覆盖三个操作的 27 种位置组合；组合不同模板的隐藏/一级/二级、启用/禁用、相同后缀不同 ID、空模板列表。
- 断言顺序、唯一性、空根和分隔线；覆盖旧全一级/全二级配置、混合无效值、保存失败、复制/导入/删除/恢复。
- 双击三个不同模板分别进入对应草稿，保存更新正确模板，取消不改动；停用模板可编辑，名称修改后仍保持原 ID 与菜单位置。
- 实现后验收编辑面板默认可见的菜单位置、已有值回填、三种选项、列表与面板双向一致，以及取消/保存失败不提交、停用模板不被自动启用；覆盖文本与 Office 模板。
- 检查单击、双击行内控件、拖动及键盘编辑入口，避免设置开关和排序时误开编辑面板；模板页不再出现“设置三个新建操作”。
- 原生验收从 Finder 连续打开混合层级菜单；App 和菜单栏三个操作仍可用；模板已有编辑、复制、默认格式和创建后行为不变。
- 原型：审核入口“2 新建与模板”，可把新建文件和 JavaScript 放一级、隐藏剪贴板文字，其余留二级，再查看菜单预览。

## T3：侧栏导航与快捷操作分开

### 已确定方案：分体新建按钮

侧栏下方保留一个独立“快捷操作”区域，与页面导航之间留出间距和分隔线。
分体按钮左侧为“新建文件… ⌘N”，点击直接打开原有新建面板；右侧下拉按钮提供两种剪贴板操作。
三个动作仍然在所有页面可用，包括关于页。菜单栏和应用 File 菜单不改变。
Finder 扩展状态链接在该区域下方以小号文字保留，它是跳转到 Finder 设置的状态入口。

这样普通新建仍为一次点击，剪贴板操作多一次选择，但侧栏从三行常驻动作压缩为一行。
审核原型保留两个版本用于历史对比；本次仅实现用户选定的分体新建按钮。

### 交互与实现

- 主按钮和下拉按钮分别有可访问名称，Tab 可以分别聚焦；原生 Menu 支持方向键、Return、Escape。
- ⌘N 在任意设置页仍然有效；避免主按钮和 Menu 重复注册同一快捷键。
- 打开已有草稿时仍只聚焦原草稿；不会读取新剪贴板内容覆盖当前草稿。
- 不把“新建”作为侧栏页面选择，不改变当前导航高亮。
- 调整 `ContentView.swift` 的操作区；继续调用现有 `PreferencesModel` 创建方法。
- 实施前更新 presentation；creation 的单面板与显式剪贴板访问规则不变。

### 验收

- 三个动作各到达原有路径；无论 Finder 菜单位置是否设为隐藏，App 入口都可用。
- 最小窗口时导航和新建操作均可到达，不出现底部按钮被挤出窗口的情况。
- 键盘和 VoiceOver 可以区分“切换页面”与“执行新建”。
- 原型：审核入口“3 快捷操作”，比较两个版本，在关于页打开新建及剪贴板操作。

## T6：让权限体验与系统授权一致

### 架构方向

沿用已选方案：主程序采用非 App Sandbox，Finder 扩展继续沙箱；文件操作由主程序负责。
继续 Developer ID、Hardened Runtime、公证和签名更新。该方案面向当前 GitHub 分发，不能直接当作 Mac App Store 方案。

保留票据的一次性、过期时间、捕获目标、配置复核、文件身份和独占写入等保护。取消沙箱不等于信任任意 URL 或取消安全检查。
菜单显示开关仍只控制功能暴露；完全磁盘访问开关属于系统，App 内不伪造可同步的 FDA 开关或全局“已授权”状态。

### T6 内部阶段与完成条件

以下为 T6 的实施阶段，任务仍保持 T1–T6 六项，不另建子任务体系。

| 阶段 | 交付范围 | 完成条件 |
| --- | --- | --- |
| 权限说明整理 | 通用页紧凑说明、文件夹页信息分组和跳转 | 文案符合当前实际权限架构，扩展状态与 FDA 说明分开；中英文、键盘与最小窗口验收通过。主程序尚未迁移时，仍需解释沙箱文件夹授权，不能提前承诺无需选择文件夹 |
| 主程序权限迁移 | 非沙箱 host、保留沙箱 extension、指定文件夹范围、全部授权入口、新旧书签生命周期及访问检查 | 下文入口清单全部完成，指定文件夹模式的迁移发布门槛通过；不依赖全位置模式 |
| 可选全位置模式 | 用户显式启用的范围模式、卷生命周期与对应菜单过滤 | 仅纳入本批交付时执行额外验收；延期时记为“未纳入本批”，产品不显示可启用入口，保留已有指定范围 |

交付记录分别说明阶段完成、未验证或延期；权限说明完成不能标成权限迁移完成，指定文件夹迁移完成也不能标成全位置模式已验证。访问检查随权限迁移阶段交付，前序说明阶段不展示尚未实现的检查控件。

### 授权入口与实现覆盖

权限迁移逐项检查下表入口，不以修改单一 helper 代替全部接入。统一顺序为：校验捕获目标、配置、范围与身份 → 尝试该操作需要的最小读写 → 根据实际失败分流。`isReadableFile` / `isWritableFile` 只能作为提示，不能代替真实操作结果或直接触发循环授权。
操作尝试仍须遵守已有确认、独占写入和批次保护；删除等操作不得为了探测权限而提前执行。

| 入口 | 当前主要落点 | 迁移要求与逐项验收 |
| --- | --- | --- |
| Finder 模板快速创建、普通新建和两类剪贴板草稿 | `PreferencesModel.handle` / `authorizeQuickCreationDirectory` / `quickCreate`；`CustomFileSavePanelController.createFile` / `authorizeForRetry`；`FolderScope` | 分离范围判断与访问结果，移除非沙箱 host 的逐目录授权前置条件及失败后的自动授权循环。已足够访问时直接执行；失败保留目标、内容、模板快照与创建后动作，恢复后由用户明确重试，不重读剪贴板或覆盖已有草稿 |
| 移动、删除、AirDrop、桌面替身等文件工具 | `FileOperationCoordinator.handle` / `authorize` | 按动作区分源读取、源目录变更和目标写入；保持删除确认、两步移动、每项身份复核和部分成功记录。拒绝、断连、取消均不重放已完成项；源、目标、Desktop 分别验收 |
| 资源工具输入与结果输出 | `FileOperationCoordinator` 的资源入口；`ResourceToolsController.authorizeOutputs` / `run` | Finder 与 App 内选择两条路径都接入。输入读取失败与输出不可写分别报告；保留显式输出目录选择，取消授权循环，原文件不变，批次失败不重做已发布输出；OCR 保存也需覆盖 |
| 使用 App 打开、创建后打开 | `OpenWithFolderAccess`、`OpenWithApplicationAccess`、`FileOperationCoordinator`、`PostCreationActionExecutor` | 分开校验目标访问、所选 App 身份和系统打开结果；非沙箱 host 不把启动 security scope 的返回值当作访问结论。打开失败保留已创建文件和明确错误，不退回其他 App、不重复创建；覆盖文件、目录和终端模式 |
| 收藏新增、定位、重新关联 | `FavoriteLocationsModel` 与 Finder 收藏请求入口 | 用户显式选择后验证整批目标与身份再保存；旧条目失效保留记录。定位、重关联和可用性检查采用一致身份规则；取消、保存失败均不留下半条记录 |
| 菜单目录添加、恢复与删除 | `PreferencesModel.addMonitoredFolder` / `removeFolder`；`FolderAccess.remember` / `restore` | 添加目录仍是用户明确修改菜单范围的动作；操作失败或访问检查不得顺带扩大范围。恢复书签不代表系统已授权；删除目录释放本次持有的访问资源并按既有规则刷新 Finder |

Core 负责确定性的范围、身份与错误分类规则；系统访问、原生面板和实际 I/O 留在现有 App / SharedUI 适配层。共享 helper 按调用方的实际访问模式处理，Finder 扩展保留沙箱约束。
每个入口分别记录足够权限、系统拒绝、只读、目标失效及适用的 NAS 断连/恢复结果；区分系统提示与 FileMint 自己的目录选择器。范围/身份失败不得靠授权重试绕过，恢复操作只由用户发起。目录选择仍可用于明确的选位置或重新关联动作。

### 通用页

将常驻的大块 FDA 引导改成紧凑的“文件访问”说明行，提供“Finder 与文件夹…”入口。
详情默认折叠，展开后说明：受保护目录由 macOS 管理；必要时在系统设置确认完全磁盘访问；说明持续显示不代表没有授权。
Finder 扩展未启用的真实状态指引仍保留，与 FDA 帮助区别呈现。

### Finder 与文件夹页

按以下顺序组织：Finder 扩展状态 → 菜单显示范围 → 文件夹访问检查 → 可折叠的系统权限说明。

- **指定文件夹**：延续现有范围；升级保留用户现有列表，不自动扩大。
- **所有支持的位置（拟议的可选模式）**：用户显式选择后才生效；只针对 Finder 能提供真实目录上下文的位置，不承诺“最近使用”、搜索聚合等虚拟位置。
- 全位置模式需验证卷挂载/卸载、网络卷与 Finder 回调。只查询卷信息，不递归扫描目录。不完成验证就不在发布版开放该选项。
- 目录列表的标题明确为“菜单显示范围”，不再把“有保存书签”展示为系统权限状态。
- “检查访问”是一次明确的用户动作，只检查所选目录。若进行写入检测，只能创建并清理独占命名的临时文件，不能修改已有文件。
- 检查结果为“本次读写成功”“当前只读”“当前无法访问”等临时结论，不保存为永久授权事实，不在后台轮询。

### 访问检查的执行与失败规则

- 点击前说明会尝试创建、读回并清理一个临时文件。开始时捕获所选目录、可校验的目录身份及请求代次；只访问该目录和本次临时文件，不枚举目录内容，不添加菜单范围、收藏或授权记录。
- 检查沿用文件操作的串行调度与 busy 状态，在后台执行实际 I/O；主线程仅显示状态。同一时刻最多一项检查，重复点击不排队。其他文件操作占用执行通道时禁用入口并说明正在处理。
- 临时文件独占创建，写入有界的固定测试内容并读回校验。使用捕获的目录与临时文件身份限制后续操作，遇到目录/文件替换即停止，不能按同名路径删除替代物。权限分类以实际错误为准；仅凭一次写入被拒不能断言 FDA 关闭或卷只读。
- 选择另一目录、离开页面或点击取消时，使当前请求结果失效并请求协作取消。旧结果不得更新新目录的状态；已创建的临时文件仍须完成安全清理。正在执行的系统/NAS 调用可能不能立即中断，界面显示“正在等待”或“正在取消”，不把等待超时或取消请求当成已经结束，也不启动替代检查。
- 从开始到实际 I/O 返回、资源释放并形成清理结果，纳入普通退出和更新重启的待完成工作保护；不可因切页或取消而提前释放。允许后续正常退出的前提是操作已结束，而非仅 UI 不再等待。
- 成功必须同时满足写入、读回和清理成功。清理失败单独报告“读写完成，但测试文件未能清理”，提供本次文件的界面定位信息及显式清理重试；不显示完整成功，不写入路径/内容日志，不后台扫描或自动重试。重试只允许处理仍匹配本次身份的临时文件。
- 实施后覆盖：重复点击、忙时点击、检查中切换目录/离页/取消、旧结果晚到、NAS 阻塞与断连、写入成功但读回或清理失败、同名替换，以及检查期间普通退出/更新重启等待。断连后的用户重试必须创建新请求，不能复用过期成功结果。

### 错误与引导

| 场景 | 用户看到什么 | 后续操作 |
| --- | --- | --- |
| 已有足够权限 | 直接完成用户发起的文件操作 | 不增加授权弹窗 |
| 受保护目录访问被拒 | “无法访问此位置，请在系统设置确认相关权限” | 系统设置入口；不能仅凭 EPERM 断言 FDA 未开启 |
| 目录或卷只读 | “此位置当前无法写入” | 检查目录/卷权限或另选输出位置，不循环要求授权 |
| NAS 断开或挂载不可用 | “网络位置当前不可用” | 用户重新连接后重试，不把断连解释为 FDA 问题 |
| NAS 服务端拒绝写入 | “共享目录没有写入权限”或保守的“此位置无法写入” | 检查共享账号权限；无法可靠归因时不武断声称原因 |
| 菜单范围以外 | 菜单不出现 | 到菜单范围设置，不引导授予 FDA |
| 旧书签失效或目标替换 | 保留记录、标明位置不可用 | 重新关联/移除；不能打开猜测的替代文件 |

### 数据与升级

- 保持生产 bundle ID、签名身份及共享 JSON 存储位置。旧偏好、模板资产、收藏和快捷项不重置。
- 旧 security-scoped bookmarks 继续作为定位/身份依据兼容读取，不能因为不再需要沙箱授予就全部删除。
- 按上方入口清单改为操作尝试与错误分流；不能把所有 EACCES/EPERM 都变成同一个授权弹窗，也不能只调整 `OpenWithFolderAccess`。
- 明确分离菜单范围、目标身份校验和系统访问结果，避免移除沙箱时顺手移除范围控制。
- `project.yml` 是配置来源，改后 `make project`；正式签名检查改为分别校验 host 与 extension。同步处理 Sparkle helper/安装设置并验证旧客户端更新。
- 实施前更新 finder-permissions、startup、updates、distribution，以及受影响的 creation、file-tools、open-with、resource-tools、favorite-locations 契约和隐私文案。权限说明先交付时，文案仍反映尚未迁移的沙箱行为。

### 新旧书签的完整生命周期

- **保存策略**：非沙箱主程序新增菜单目录、收藏、所选 App（包括创建后打开的独立 App 注册表）时，使用普通定位书签并保存各域需要的身份信息，不把书签称为系统权限授予。书签类型以兼容的可选元数据区分；旧记录缺少该字段时按旧 security-scoped 格式读取，未知/损坏类型保留原记录并报告不可用，不能猜测格式覆盖原数据。具体字段落在现有存储中，不另建重复目录或 App 列表。
- **旧记录读取**：保留原始书签、稳定条目 ID 和既有身份信息，先解析，再校验范围、目标类型及身份。`startAccessingSecurityScopedResource` 返回 false 本身不等于非沙箱 host 无权访问，也不允许跳过身份校验；成功启动的 scope 仍须配对释放。启动时不批量改写、清空或后台探测全部记录。
- **新增与取消**：仅在用户选定目标且验证成功后原子保存定位书签与身份数据。取消选择、验证失败或保存失败保留原记录，不提交半成品；添加 App 不启动 App，添加收藏不扩大菜单范围。
- **过期刷新**：仅在显式使用时解析到原对象、身份与范围校验通过后，生成新的普通定位书签，连同类型元数据原子替换该条记录。刷新失败保留旧字节；若本次已可靠验证原对象且实际操作可行，刷新失败不伪装成目标失效，也不默默丢弃记录。
- **移动与替换**：收藏及所选 App 可按所属契约定位移动后的原对象，继续验证文件身份或 App 标识；不自动改用同名目标或另一份 App。菜单范围目录及访问 helper 的目录记录保持既有范围规则，路径变化不能隐式扩大范围，需用户明确重新关联。解析失败、身份不匹配或证据不足时保留条目并提供重新关联/移除。
- **重新关联与删除**：重关联必须重新选择并按所属域规则校验，保存失败保持原条目，保存成功只替换目标与对应书签/身份；删除只清理该记录及其自有元数据并释放访问资源，不删除目标文件。显式修改菜单目录才更新 Finder 范围。
- **验收矩阵**：对菜单目录、收藏、Finder 所选 App、创建后打开 App 分别覆盖旧记录升级读取、新增后重启、过期刷新成功/失败、目标移动、同名替换、重新关联取消/保存失败/成功、删除，以及适用的网络卷重挂载。旧定位记录与新定位记录混合时合法邻项不能丢失；配置损坏时沿用现有保留证据规则。操作 helper 的旧目录书签也需覆盖解析、身份拒绝和释放。
- 新增与刷新策略必须通过支持系统上的签名原生验收后才用于正式迁移；旧原型中“已有书签可读取”的结果不作为新记录可写或可重启恢复的证据。
