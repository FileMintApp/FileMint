# FileMint UI / UX 提案 01

Status: implemented; native installed-build acceptance pending
用户选择：原生 macOS、通透克制、薄荷绿点缀。2026-09-18 用户确认导航分层后要求开始实现。

## 方向

- 强调操作对象、预览与下一步；不添加统计面板、使用次数或虚构效率指标。
- 系统字体、原生标题栏、温和的侧栏材质、清晰的间距与对齐；薄荷绿用于选中和主要操作。
- 使用柔和中性色区分侧栏、内容、参数区域；避免每项操作都有独立彩色大图标或装饰卡片。
- 明暗两种外观使用同一套布局和语义；小字号只用于辅助信息，主要操作和状态保持清晰。

## 信息结构

- 文件创建：模板与类型、创建行为，独立于扩展功能。
- 扩展功能：文件工具、资源工具；后续新增工具统一归入这一组，不预置空入口。
- 偏好设置：通用、Finder 与文件夹、关于。
- “新建文件”固定在侧栏底部，保留 ⌘N；实际 Finder 创建仍只打开创建面板。
- 资源工具分为“使用工具”和“Finder 菜单设置”。主应用直接选择图片进入处理已纳入本次实现契约，独立于 Finder 菜单开关。
- 模板与类型先覆盖现有单后缀类型管理，不把规划中的多模板、分组或收藏当成已实现功能。

## 主要界面

### 设置与工具管理

统一标题、说明、分组、开关、右侧选项及辅助操作。总开关状态单独呈现；子功能行保留说明，选项位置固定。
通用页只包含实际偏好，不做数据概览；授权页明确区分菜单范围、目录书签与系统权限。

### 图片处理

通过主应用工具入口或 Finder 选中图片进入同一个工作流；Finder 路径继续使用独立原生面板，不自动弹出设置。

- 左侧：当前图片预览、必要尺寸信息、批次缩略图；拼图展示组合后的布局。
- 右侧：只显示当前操作的参数、输出位置和一条简短结果说明。
- 底部：一个主操作，配合进度与取消；完成后在相同位置切换为查看结果。
- OCR 使用“原图—识别文字”关系，不把大量文本追加到参数表单末尾。
- 常规流程不堆叠内存、SDK 或编码器术语；超限时再显示具体原因和可调整的参数。
- 预览只承诺布局、尺寸和透明背景等可确定信息；压缩体积在实际编码后显示，禁止随滑块伪造估算数字。

### 新建文件

完整文件名 → 保存位置 → 可选初始内容；保持紧凑，强调文件名和创建按钮。支持键盘操作，取消保留原目录和已有文件。

## 性能与隐私约束

- 原生实现以 SwiftUI/AppKit 控件与系统材质为主；材质限于少数窗口区域，不全屏叠加实时模糊。
- 无常驻动效、轮询、后台扫描或预热模型；尊重减少动态效果。
- 预览使用有界缩略图、合并参数变更、串行解码；全尺寸处理只在确认后发生。
- 批次结果只属于当前会话，不新增历史、遥测或资源上传。
- 设计稿中的图片、已启用状态和结果为示例；原型不修改实际文件、偏好或剪贴板。

## 实施与验证

- 2026-09-18 用户认可视觉方向，要求模板独立分层、后续扩展集中管理；导航已调整为文件创建 / 扩展功能 / 偏好设置。
- 已采用“预览 + 右侧参数 + 底部动作”的原生处理面板，OCR 为原图/文字分栏；压缩体积不做伪估算。
- 已加入主应用显式选图入口，Finder 开关关闭仍可使用；更多限制折叠展示，运行错误就近说明。

- 通过原生面板创建的 Unicode Markdown 名称及正文 UTF-8 字节已核对；未替换现有安装应用。
